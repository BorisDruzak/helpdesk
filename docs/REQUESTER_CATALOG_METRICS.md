# Метрики пути создания обращения

`POST /api/web/requester/catalog-events` принимает только текущих user/admin.
Лимит —120 событий в минуту на аутентифицированного актёра; тело ограничено1024
байтами, включая chunked. Обязательные поля: случайный UUID `flow_id`,
`sequence`1..10000, `event`, `elapsed_ms`0..86400000, `rank`0..50,
`result_count`0..50. Посторонние поля и неверные типы отвергаются.

События: opened, search_ready, result_selected, service_selected, service_changed,
catalog_selected, fallback_selected, submitted, abandoned. Записываются только
эти поля в серверный журнал `[catalog_funnel]`; текст запросов, ответы, коды услуг,
идентификаторы сотрудника и обращения не принимаются. UUID не является токеном
доступа; он новый при открытии страницы и не сохраняется в cookie/storage.

Provider охватывает страницу создания: смена услуги или именованного входа не
создаёт новый flow. Уход со страницы/pagehide регистрируется один раз; подтверждённая
клиентом отправка завершает flow без abandoned. Восстановление из bfcache начинает
новое наблюдение. Повтор effect в StrictMode не создаёт ложный отказ. Метрики
асинхронны, используют keepalive и никогда не блокируют заявку при ошибке доставки.

Это best-effort измерения клиента, а не источник истинного количества заявок.
Блокировщики, закрытие браузера, потеря сети и повтор идемпотентного результата
создают неопределённость; submitted нельзя использовать как бизнес-аудит.
`rank` — позиция в отфильтрованном ответе поиска;0 означает выбор вне ранжированной
выдачи. `result_count` относится к совпадениям, а не видимым трём строкам группы.

Для сводки экспортируйте журнал только Helpdesk staging и запустите:

```powershell
python scripts/catalog_funnel_report.py <journal-export.txt>
```

Отчёт запускается стандартным Python без загрузки серверного окружения.
Сводка дедуплицирует flow+sequence, считает пустую выдачу, выборы в первых пяти,
смены услуги, наблюдаемые отправки/выходы и медианное время до отправки. Незавершённые
flows отдельно помечены как incomplete/unobserved, а не автоматически отказавшие.
Окно журнала должно включать начало пути; окно без opened не входит в конверсию.
Данные хранятся по существующей политике journal rotation, отдельная БД не создаётся.
