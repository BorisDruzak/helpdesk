# Студия обращений: полный гайд по кликам

> Историческая инструкция для интерфейса от 13 октября 2026 года. После перехода
> к единой модели услуги отдельное создание обычных форм и ряд описанных ниже
> экранов больше не используются. Актуальный порядок создания услуг, настройки
> условий, правил и импорта JSON/YAML: [Единая студия услуг](UNIFIED_SERVICE_SCENARIOS.md).

Версия инструкции: 13 октября 2026 года. Инструкция сверена с интерфейсом staging и реализацией релиза `4e2ae7acba8c4c936638d7b9262803e61a2ea592`.

Страница: **Администрирование → Каталог и обращения → Студия обращений**. Открывается **Каталог услуг**. Вкладки «Карты сценариев» в каталоге больше нет: карту открывают из настроек конкретной услуги.

Названия в кавычках — надписи кнопок, вкладок и полей. После каждого маршрута по кликам указано, что должно получиться. Набор шаблонов, политик, очередей и согласующих зависит от настройки вашего Helpdesk; в примерах используйте подходящие действующие объекты своего каталога. Для быстрого поиска кнопки используйте поиск по документу (обычно Ctrl+F). Последний раздел содержит краткий указатель действий.

## 1. Термины и выбор способа создания

### 1.1. Что за что отвечает

| Объект | Для чего нужен | Пример |
| --- | --- | --- |
| Раздел каталога | Крупная область помощи, объединяющая категории и услуги | «Рабочее место», «Сеть» |
| Категория | Необязательная папка внутри раздела; может содержать вложенные категории | «Принтеры и МФУ» |
| Услуга | Пункт, который сотрудник выбирает в каталоге | «Застряла бумага», «Нужен доступ» |
| Обычная форма | Сотрудник сразу заполняет поля формы; карта переходов не нужна | Форма заказа оборудования |
| Карта сценария | Вопросы, инструкции, развилки и результаты, связанные стрелками | Самопомощь при проблеме с печатью |
| Точка входа, пункт каталога | Связывает название услуги с первым шагом общей карты | «Застряла бумага» начинает карту с инструкции по замятию |
| Тип создаваемого обращения | Общая привязка карты к настройкам заявки; определяет связанный шаблон | «Проблема с принтером» |
| Класс обращения | Общая классификация: инцидент, запрос услуги, запрос доступа и т. п. | «Инцидент» — что-то перестало работать |
| Шаблон обработки, шаблон заявки | Определяет форму, необходимые данные и ссылки на правила обработки | Шаблон «Запрос доступа» |
| Политика | Правило выбора очереди, приоритета, сроков, согласования и т. п. | Политика маршрутизации в поддержку рабочих мест |
| Черновик | Сохранённая, но ещё не применённая версия карты | Новая ветвь только для администратора |
| Опубликованная версия | Проверенная версия, по которой идут сотрудники | Версия 3 маршрута |

Иерархия каталога: **раздел → необязательная категория → услуга**. Сценарий и шаблон обработки — настройки услуги, а не папки этого дерева. В дереве и центральном списке повторяются те же услуги; это два способа выбрать один объект.

Несколько услуг могут использовать разные входы одной карты. У них общие блоки и общий тип обработки. Изменение общих блоков затрагивает все входы этой карты после её публикации.

### 1.2. Какой путь выбрать

| Что хотите сделать | Путь |
| --- | --- |
| Сотрудник должен сразу заполнить форму | «Создать услугу» → «Обычная форма · новый тип обращения» |
| Нужны вопросы и передача в поддержку | «Создать услугу» → «Новая услуга с пошаговым сценарием» → «Простая заявка» |
| Нужна инструкция с вопросом «Помогло?» | Тот же путь → «Диагностика проблемы» |
| Хотите собрать маршрут вручную | Тот же путь → «Пустая карта» |
| Новое название услуги должно вести в уже существующую карту | «Создать услугу» → «Вход в существующий сценарий» |
| Услуга с обычной формой уже есть, хотите добавить карту | Выбрать услугу → «Помощь сотруднику» → «Создать карту» |
| Хотите изменить существующую карту | Выбрать услугу → «Открыть карту сценария» |

Создание и редактирование Студии доступны администратору. Аудитор может просматривать и тестировать сохранённые сценарии, но не изменять и не публиковать их. Для создания шаблона дополнительно нужно право публикации форм. Серые кнопки могут означать отсутствие прав, незаполненные данные, несохранённые изменения или выполняющийся запрос.

### 1.3. Три разных проверки

| Действие | Что проверяет | Что не происходит |
| --- | --- | --- |
| «Как у сотрудника», «Предпросмотр страницы» | Тексты, расположение и оформление вопросов текущего черновика | Не проходит реальные условия маршрута и не создаёт заявку |
| «Тестировать» | Серверные переходы, ответы и расчёт обработки сохранённого черновика | Не создаёт обращение, согласование, уведомление или операцию устройства |
| «Опубликовать» → «Подготовить публикацию» | Готовность карты и действующих правил к применению | Само открытие панели ещё не публикует карту |

## 2. Экран каталога: все основные кнопки

Экран состоит из дерева слева, списка услуг в центре и настроек выбранной услуги справа.

| Элемент | Что сделать и что получится |
| --- | --- |
| «Создать услугу» | Открывает форму создания справа с выбором способа помощи |
| «Поиск услуг» | Введите название, описание или поисковую фразу; центральный список отфильтруется |
| «Статус» | Выберите состояние, доступность или способ помощи |
| «Все услуги» | Снимает выбор раздела/категории; введённый поиск и другие фильтры могут оставаться |
| Название раздела | Показывает услуги этого раздела в центре |
| Название категории | Показывает услуги этой категории и её вложенных категорий |
| Стрелка слева от раздела/категории | Сворачивает или разворачивает ветку; услуги не удаляются |
| Название услуги в дереве | Открывает её настройки справа, сбрасывает поиск и фильтр состояния, выбирает расположение услуги |
| Строка услуги в центре | Открывает те же настройки справа |
| «+» у заголовка «Структура каталога» | Создаёт новый раздел |
| «…» у раздела | Открывает настройки раздела |
| «…» у категории | Открывает настройки категории |
| «Создать категорию» | Создаёт категорию в выбранном разделе; при выбранной категории — внутри неё |
| «Сортировка услуг» | «По названию» или «По изменению карты» |
| «Предыдущая страница», «Следующая страница» | Переключают страницы центрального каталога, если они есть |
| Вертикальные границы между панелями | Перетащите, чтобы изменить ширину; размер запоминается в браузере |
| «Повторить», «Повторить обновление каталога» | Повторяют неудавшуюся загрузку, если показана ошибка |
| «×» в настройках услуги | Закрывает выбранную карточку; при несохранённых правках потребуется решение |

Пункты фильтра «Статус»: «Все состояния», «Доступны сотрудникам», «Недоступны сотрудникам», «Обычная форма», «Пошаговый сценарий», «Есть черновик карты», «Ошибки черновика карты», «Есть архив карт».

Дерево загружает услуги независимо от поиска центрального списка. Поэтому при результате «Услуги не найдены» соседние услуги могут оставаться в дереве. Если дерево не удалось загрузить полностью, нажмите его «Повторить».

### Что означают подписи строки

- **«Обычная форма» / «Пошаговый сценарий»** — способ помощи; у действующей услуги учитывается опубликованное состояние. Неопубликованная карта не заменяет действующую форму.
- **«Доступна сотрудникам»** — выполнены условия доступности каталога и формы/сценария.
- **«Недоступна сотрудникам»** — пункт ещё нельзя использовать из кабинета сотрудника.
- **«Изменения черновика»** — есть отдельные изменения, которые ещё не применены публикацией карты.
- **«Ошибки черновика карты»** — черновик требует исправления; действующая опубликованная версия при этом может продолжать работать.
- **«Типов обработки»** внизу — количество базовых типов, а не обязательно количество видимых названий услуг: одна карта может давать несколько входов.

## 3. Создание раздела и категории

### 3.1. Новый раздел

1. Откройте каталог.
2. В панели «Структура каталога» нажмите «+» у заголовка.
3. Справа появится «Новый раздел каталога».
4. Заполните «Название раздела», например «Оборудование».
5. Заполните «Описание раздела» — короткое пояснение области помощи.
6. В «Обработка новых услуг» выберите «Как в разделе …», если хотите взять базовые настройки существующего опубликованного раздела. «Настроить позднее» не подставляет такие настройки.
7. Нажмите «Сохранить раздел».
8. Найдите новый раздел в дереве и нажмите рядом «…».
9. Для сохранённого черновика нажмите «Опубликовать раздел».
10. Прочитайте подтверждение и нажмите «Подтвердить публикацию раздела».

Результат: раздел прошёл серверную проверку и может использоваться для новых услуг. Если публикация не прошла, исправьте настройки; сохранение черновика само по себе не означает доступность сотрудникам.

«Обработка новых услуг» копирует базовые привязки очередей и политик раздела-образца при создании нового раздела. Это не кнопка изменения существующего раздела-образца.

| Кнопка | Назначение |
| --- | --- |
| «Сохранить раздел» | Сохраняет название, описание и первоначальные настройки нового раздела |
| «Отмена» | Закрывает форму; несохранённые изменения можно потерять только после подтверждения |
| «Опубликовать раздел» | Открывает подтверждение публикации сохранённого черновика |
| «Подтвердить публикацию раздела» | Запускает публикацию после серверной проверки |
| «Отмена публикации» | Закрывает подтверждение, не публикуя раздел |

### 3.2. Новая категория или вложенная категория

1. В дереве выберите нужный раздел. Для вложенной категории сначала выберите родительскую категорию.
2. Нажмите «Создать категорию».
3. Заполните «Название категории», например «Принтеры и МФУ».
4. Проверьте «Раздел каталога». При создании из выбранного раздела он может быть зафиксирован.
5. В «Родительская категория» выберите папку либо «В основном разделе».
6. Откройте «Расширенные настройки».
7. При необходимости заполните описание.
8. Для категории, через которую сотрудники должны видеть опубликованные входы, выберите подходящую публичную видимость и опубликованное состояние. По умолчанию новая категория создаётся **внутренней и в черновике**.
9. Нажмите «Сохранить категорию».

| Поле | За что отвечает |
| --- | --- |
| «Название категории» | Название папки в дереве |
| «Раздел каталога» | Область, к которой относится папка; у существующей категории не меняется через эту форму |
| «Родительская категория» | Вложенность внутри того же раздела |
| «Код категории» | Технический код; создаётся автоматически. Допустимы строчные латинские буквы, цифры, `_`, `-` |
| «Описание категории» | Пояснение назначения |
| «Видимость» | «Публичная», «Внутренняя», «Ограниченная». Публичная дочерняя категория не обходит ограничения родительской |
| «Состояние категории» | «Черновик», «Опубликована», «Архив» |
| «Порядок» | Числовой порядок категории; это не порядок выполнения блоков карты |

Для изменения: нажмите «…» у категории, исправьте поля, нажмите «Сохранить категорию».

Для перемещения: поменяйте «Родительская категория» и сохраните. Нельзя выбрать саму категорию или её потомка; перенос между разделами этой формой не выполняется.

Для архива: сначала переместите вложенные категории, услуги и привязанные карты/входы; сохраните правки. Нажмите «Архивировать категорию» → «Подтвердить архивирование». «Оставить категорию» отменяет подтверждение. Сервер не разрешает архивировать непустую категорию.

На карте есть ещё «Создать категорию здесь»: она создаёт папку в разделе текущей карты и выбирает её для карты. Закройте или сохраните эту форму прежде, чем переходить к другим действиям карты.

## 4. Создание услуги с обычной формой

Обычная форма подходит, если сотруднику достаточно сразу заполнить поля и отправить обращение. Карта и точки переходов не нужны.

1. Нажмите «Создать услугу».
2. В «Способ помощи» оставьте «Обычная форма · новый тип обращения».
3. В «Раздел каталога» выберите опубликованный публичный раздел.
4. Введите «Название услуги», например «Заказать клавиатуру».
5. Введите «Краткое описание услуги», например «Нужна новая клавиатура или замена неисправной».
6. В «Шаблон обработки» выберите действующий опубликованный шаблон с подходящими вопросами и правилами.
7. Если нужно, откройте «Расширенные настройки обращения» и измените «Класс обращения».
8. Нажмите «Создать черновик услуги».
9. В открывшихся настройках услуги перейдите в «Основное», выберите категорию и добавьте слова для поиска. Нажмите «Сохранить», если внесли изменения.
10. Перейдите в «Доступность» и проверьте «Видимость услуги».
11. Если внесли изменения видимости, сначала нажмите «Сохранить».
12. Нажмите «Опубликовать услугу» → «Подтвердить публикацию услуги».
13. Убедитесь, что состояние стало доступным сотрудникам. При доступности используйте «Открыть в кабинете сотрудника» для проверки настоящей формы.

Результат: опубликована услуга с обычной формой. В настоящем кабинете кнопка отправки создаёт реальное обращение; предпросмотр карты и симулятор этого не делают.

### Поля и кнопки создания

| Элемент | Назначение |
| --- | --- |
| «Способ помощи» | Выбирает создание формы, новой карты или входа в существующую карту |
| «Раздел каталога» | Размещение услуги и базовые настройки наследования |
| «Название услуги» | Название, которое выбирает сотрудник |
| «Краткое описание услуги» | Объясняет, в каком случае выбирать эту услугу |
| «Шаблон обработки» | Связывает услугу с обычной формой и правилами обработки |
| «Класс обращения» | Инцидент, общий запрос, запрос услуги, запрос доступа, установка ПО, консультация; «Установка ПО» использует класс запроса услуги с соответствующим профилем |
| «Создать шаблон» | Открывает отдельную вкладку создания шаблона |
| «Обновить список шаблонов» | Перечитывает шаблоны после их публикации; введённое название услуги сохраняется в текущей форме |
| «Повторить загрузку шаблонов» | Повторяет загрузку при ошибке |
| «Создать черновик услуги» | Сохраняет новый тип/услугу; не создаёт карту и не публикует автоматически |
| «Отмена» | Закрывает создание; при внесённых данных спрашивает об отказе от сохранения |

Если «Создать черновик услуги» недоступна, проверьте название, опубликованный раздел и выбранный действующий шаблон. Пустой список разделов означает, что сначала нужно подготовить публичный опубликованный раздел.

## 5. Создание собственного шаблона обычной формы

Этот путь нужен, если ни один действующий шаблон не задаёт нужные вопросы. Один шаблон может использоваться несколькими услугами.

1. В создании услуги нажмите «Создать шаблон». Откроется отдельная вкладка «Создать шаблон».
2. Введите «Название шаблона», например «Заявка на оборудование».
3. Заполните «Описание шаблона».
4. В «Тип обращения» выберите «Инцидент — что-то не работает», «Запрос услуги», «Запрос доступа» или «Консультация».
5. В разделе «Что спросить у сотрудника» отредактируйте первый вопрос.
6. Нажмите «Добавить вопрос» столько раз, сколько нужно.
7. Для каждого вопроса задайте название, тип ответа и обязательность.
8. Откройте «Как обрабатывать обращение».
9. Выберите опубликованные политики либо оставьте «Наследовать настройки».
10. Нажмите «Опубликовать шаблон».
11. Прочитайте подтверждение. «Продолжить редактирование» возвращает к полям.
12. Нажмите «Подтвердить публикацию шаблона».
13. Дождитесь сообщения «Шаблон опубликован …».
14. Вернитесь во вкладку создания услуги.
15. Нажмите «Обновить список шаблонов» и выберите новый шаблон.
16. Продолжите создание услуги по разделу 4.

| Поле/кнопка | Назначение |
| --- | --- |
| «Название шаблона» | Понятное администратору имя в списке шаблонов |
| «Описание шаблона» | Поясняет назначение шаблона |
| «Тип обращения» | Класс заявки, связанной с этим шаблоном |
| «Название вопроса N» | Текст вопроса сотруднику |
| «Тип ответа N» | В этом упрощённом создании доступны «Короткий текст», «Подробный ответ», «Да / нет» |
| «Обязательный ответ N» | Требует заполнения соответствующего вопроса |
| «Удалить вопрос N» | Удаляет вопрос; последний оставшийся вопрос удалить нельзя |
| «Добавить вопрос» | Добавляет ещё одно поле |
| «Как обрабатывать обращение» | Очередь и маршрут, приоритет, сроки обслуживания, внутренние сроки, согласование, закрытие, видимость, уведомления |
| «Опубликовать шаблон» | Открывает подтверждение, пока ещё без публикации |
| «Подтвердить публикацию шаблона» | Публикует новый шаблон и его форму |
| «Продолжить редактирование» | Отменяет подтверждение и позволяет исправить поля |
| «Вернуться в конструктор» | Открывает общий конструктор форм; при несохранённых правках действует предупреждение |
| «Повторить» при ошибке загрузки | Перечитывает правила обработки |

Этот упрощённый экран не содержит всего набора полей карты: здесь нет списков, выбора устройств или сложных условий. Для их настройки используйте существующий конструктор через «Открыть обычную форму»/«Открыть шаблон обработки» либо задавайте пошаговые вопросы в карте. Не ищите «Несколько вариантов» на экране простого создания шаблона — это тип ответа редактора вопросов карты.

Публикация шаблона не публикует услугу или карту и не перепубликовывает выбранные политики. После неё услугу всё ещё нужно сохранить и опубликовать отдельно.

## 6. Четыре вкладки настроек услуги

Выберите услугу в дереве или центральном списке. Справа доступны «Основное», «Помощь сотруднику», «Обработка обращения», «Доступность».

### 6.1. Заголовок и общие действия

| Элемент | Назначение |
| --- | --- |
| Название и доступность | Показывают выбранную услугу и состояние для сотрудников |
| «Открыть карту сценария» | Открывает связанную карту; для отдельного входа выбирает его начальный шаг |
| «Открыть карту сценария: …» | Позволяет явно выбрать нужную карту, если их несколько |

### 6.2. «Основное»

## 7. Создание новой карты: три основы

### Общий путь

1. В каталоге нажмите «Создать услугу».
2. В «Способ помощи» выберите «Новая услуга с пошаговым сценарием».
3. Нажмите «Создать карту».
4. В окне «С чего начнём?» задайте «Название карты».
5. В «Раздел каталога» выберите раздел или категорию нужного раздела.
6. Выберите основу в «Способ начала работы».
7. Откройте раскрываемый пункт «Тип обращения · можно выбрать в результате».
8. В «Тип создаваемого обращения» выберите подходящий существующий тип с шаблоном. Если не выберете сейчас, потребуется сделать это на карте до серверного сохранения.
9. Если нужного типа нет, нажмите «Создать новый тип обращения», заполните форму услуги и нажмите «Создать черновик услуги». Это отдельное серверное сохранение, а не только настройка окна.
10. Нажмите «Создать карту →».
11. Проверьте созданные шаги, вход, вопросы и привязку результата.
12. Нажмите «Сохранить черновик» после настройки необходимых данных.

Сама кнопка «Создать карту →» создаёт редактируемую локальную схему. Пока она не сохранена на сервере, её можно потерять при отказе от правок. Она не публикуется автоматически.

| Поле/кнопка окна | Назначение |
| --- | --- |
| «Название карты» | Имя маршрута для администратора; основы также используют его для первоначального пункта каталога |
| «Раздел каталога» | Область карты; может быть зафиксирована при создании из конкретной услуги |
| «Простая заявка» | Вопрос → сводка → обращение |
| «Диагностика проблемы» | Инструкция → проверка результата → решение либо поддержка |
| «Пустая карта» | Пустая схема для ручной сборки |
| «Будет создано» | Поясняет выбранную основу |
| «Тип создаваемого обращения» | Общая форма/обработка для карты |
| «Создать новый тип обращения» | Встраивает создание новой услуги-черновика с шаблоном |
| «Создать карту →» | Переходит к локальной схеме |
| «Отмена», «×» | Закрывают мастер; несохранённые данные вложенного создания типа защищены предупреждением |

### 7.1. «Простая заявка»

Создаются:

- вход с названием карты;
- вопрос «Что нужно сотруднику?» с текстом «Что вам необходимо?»;
- сводка «Проверка ответов»;
- результат «Создать обращение».

Вопрос, сводка и результат уже связаны. Замените общий вопрос на конкретный и добавьте обязательные вопросы выбранного типа обращения. Не считайте автоматически созданную основу готовой к публикации.

### 7.2. «Диагностика проблемы»

Создаются инструкция «Первый шаг решения», проверка «Проблема решена?», завершение без обращения, сводка «Передать в поддержку» и создание обращения.

«Да» ведёт к завершению без обращения; «Нет» и запасной путь для «Не знаю» — к поддержке. Эта основа — маршрут самопомощи. Она **не означает**, что на устройстве автоматически запустится диагностика.

### 7.3. «Пустая карта»

1. После создания нажмите «+ Добавить первый шаг» либо «+ Вопрос» в библиотеке.
2. Задайте первый вопрос.
3. Добавьте необходимые остальные блоки.
4. Соедините их по разделу 11.
5. Настройте основной вход и явный пункт каталога.
6. Добавьте результат маршрута.
7. Выберите тип создаваемого обращения до первого серверного сохранения.

Пустую карту нельзя считать настроенной только по наличию блоков: нужны вход, связи и законченные маршруты.

## 8. Добавление сценария к существующей услуге

1. Найдите обычную услугу в каталоге.
2. Откройте её настройки.
3. Перейдите в «Помощь сотруднику».
4. Нажмите «Создать карту».
5. В окне проверьте название. Раздел и связанный тип уже определены услугой.
6. Выберите «Простая заявка», «Диагностика проблемы» или «Пустая карта».
7. Нажмите «Создать карту →».
8. Настройте вопросы, входы, результат и политики.
9. Сохраните, протестируйте и опубликуйте карту.

До публикации новой карты сотрудник продолжает пользоваться действующей обычной формой, если услуга доступна. Если карта уже есть, используйте «Открыть карту сценария», а не создавайте дубликат.

## 9. Несколько услуг на одной карте

### 9.1. Новый пункт из каталога

1. Нажмите «Создать услугу».
2. В «Способ помощи» выберите «Вход в существующий сценарий».
3. В «Найти карту» введите часть названия при необходимости.
4. В «Карта сценария» выберите существующую карту.
5. Если список длинный, используйте «Предыдущие карты»/«Следующие карты».
6. Введите «Название новой услуги», например «Застряла бумага».
7. В «Точка входа» выберите реальный первый шаг этой услуги.
8. Нажмите «Создать черновик пункта».
9. В появившейся карточке услуги заполните описание, категорию и поисковые фразы. Сохраните изменения.
10. Нажмите «Открыть карту сценария».
11. Проверьте вход и пройдите его через «Тестировать».
12. Опубликуйте общую карту.

Результат: добавлен новый вход с отдельным названием, без создания ещё одного базового типа обработки. Сотрудники увидят новый пункт после подходящей публикации и проверки доступности.

«Повторить» перечитывает список карт; «Повторить загрузку карты» перечитывает выбранную карту. При конфликте пункт не создаётся поверх чужих изменений: сначала получите актуальную карту и повторите создание.

### 9.2. Новый пункт прямо на карте

1. Выберите блок, с которого должен начинаться отдельный вход.
2. Справа раскройте «Пункты каталога для этого шага».
3. Нажмите «Добавить точку входа из каталога».
4. Настройте поля нового пункта.
5. Сохраните карту.
6. Протестируйте каждый вход и опубликуйте карту.

В «Настройки карты» также есть «Добавить пункт каталога для блока»: выберите первый блок. Для совместимого основного входа на пункте/пунктирной связи может быть кнопка «Создать пункт каталога для входа».

У совместимого входа кнопка «Убрать основной вход из черновика» снимает назначение основного начального блока, но не удаляет сам блок. После этого назначьте новый основной вход или настройте допустимые отдельные входы и проверьте готовность. Действующая опубликованная версия не заменяется этим локальным действием.

| Поле/кнопка входа | Назначение |
| --- | --- |
| «Название пункта» | Отдельное название услуги в каталоге |
| «Краткое описание» | Когда выбирать этот вход |
| «Категория пункта» | Отдельная папка либо «Категория карты» |
| «Синонимы и поисковые фразы» | Поиск этого входа; одна фраза на строку |
| «Начальный блок» | Первый реальный шаг выбранного входа |
| «Сообщённый симптом» | Предварительная формулировка проблемы; не является доказанным фактом диагностики |
| «Доступен в каталоге» | Включает пункт в настройки следующей публикации |
| «Видимость» | Для сотрудников, внутренний или ограниченный |
| «Расширенные настройки пункта» | Показывает стабильный ключ входа |
| «Убрать точку входа из черновика» | Удаляет её из редактируемой версии; действующая публикация меняется после новой публикации |
| «Добавить точку входа из каталога» | Добавляет ещё один пункт к выбранному блоку |

Несколько входов могут вести на один шаг. Переназначить вход можно через «Начальный блок», «Точка входа» в карточке услуги или переназначение пунктирной связи.

Не начинайте вход после вопросов, ответы которых требуются дальше: для этого входа они не будут собраны. Все пути к созданию обращения должны получить необходимые данные шаблона.

### 10.3. Левая библиотека

- «+ Вопрос», «+ Инструкция», «+ Условие», «+ Проверка результата», «+ Диагностика», «+ Сводка», «+ Результат» добавляют соответствующий блок.
- «Найти шаг · расположение панелей» раскрывает поиск «Найти блок» и «Сбросить размеры панелей».
- Название блока в списке выбирает его и приближает к нему карту.
- «Настройки карты» открывает системные настройки справа.
- «Точки входа · N» перечисляет входы. Нажмите название, чтобы выбрать его начальный блок.

### 10.4. «Настройки карты»

Откройте их кнопкой на карте, в библиотеке или выбором системного элемента.

| Поле | Назначение |
| --- | --- |
| «Добавить пункт каталога для блока» | Создаёт явный вход каталога к выбранному первому шагу |
| «Название карты» | Название общего маршрута; не обязано совпадать со всеми названиями входов |
| «Описание» | Пояснение карты и текста в её предпросмотре |
| «Раздел» | Показывает область карты |
| «Категория карты (необязательно)» | Папка по умолчанию для карты и входов, наследующих её категорию |
| «Создать категорию здесь» | Создаёт вложенную папку в контексте карты |
| «Основной вход карты» | Начальный блок совместимого основного маршрута; отдельные пункты имеют собственные начальные блоки |
| «Расширенные настройки» → «Поиск типа обращения» | Помогает найти базовую обработку у новой карты |

Системные настройки карты не выполняются как вопрос сотруднику. Пунктирная связь от входа к блоку задаёт старт, обычная стрелка между блоками — дальнейший переход.

## 11. Добавление, соединение, копирование и удаление блоков

### 11.1. Добавить следующий шаг с автоматической связью

1. На нужном блоке нажмите «+ Добавить следующий шаг».
2. В «Что добавить дальше?» выберите действие.
3. Новый шаг появится на карте и откроется справа.
4. Заполните его настройки.
5. Проверьте созданную стрелку.

В меню есть «Спросить сотрудника», «Показать инструкцию», «Проверить результат», «Добавить условие», «Выполнить диагностику», «Показать сводку», «Создать обращение», «Завершить без обращения». «×» закрывает меню.

Если вставка могла бы потерять существующие ветви или после конечного результата невозможен следующий шаг, редактор объяснит ограничение. «Добавить отдельно и настроить ветви» создаёт самостоятельный блок; после этого соедините его явно.

### 11.2. Добавить отдельный блок

Нажмите «+ …» в библиотеке либо перетащите тип блока на карту. Такой блок нужно проверить на наличие входящих и исходящих связей; само добавление не означает, что сотрудник до него дойдёт.

### 11.3. Соединить два блока

Способ с выбором из списка:

1. Нажмите исходный блок.
2. В его настройках найдите «Переходы».
3. В «Соединить с блоком» выберите целевой шаг.
4. На карте появится стрелка.
5. Если нужна проверка ответа, нажмите стрелку и настройте условие.

Способ мышью:

1. Наведите на выходную точку справа исходного блока.
2. Перетащите связь к входной точке слева целевого блока.
3. Отпустите и проверьте направление стрелки.

Для «Условие» и «Проверка результата» удобнее использовать «Добавить условную ветвь» и «Если ни одно условие не выполнено» — разделы 14–15.

Запрещённый автоматический цикл не сохраняется: редактор покажет ошибку. Вернуться к предыдущему вопросу в тестировании/кабинете можно штатной кнопкой «Назад», а не циклом стрелок.

### 11.4. Изменить связь или вставить шаг между двумя блоками

1. Нажмите обычную стрелку либо её запись «Продолжить → …»/«Условие → …» в инспекторе исходного блока.
2. Справа откроется «Переход из …».
3. Измените «Следующий блок», если нужно перенаправление.
4. Настройте «Условие перехода», если нужен выбор по ответу.
5. В «Расширенные условия» настройте «Приоритет сопоставления», если условия могут совпасть.
6. Для вставки выберите «Вставить блок на связь» → «Вставить между шагами».

Условие старой стрелки остаётся на первой связи, новый шаг продолжает прежний маршрут. Вставка развилки или конечного результата может потребовать отдельного добавления с явными ветвями.

При перетаскивании блока из библиотеки на стрелку появляется подтверждение «Вставить между шагами» / «Отмена вставки». Пунктирный вход не является обычной связью для такой вставки.

| Кнопка связи | Назначение |
| --- | --- |
| «Переместить переход в конец» | Переставляет выбранную связь после остальных; полезно для запасного пути |
| «Вставить между шагами» | Добавляет выбранный тип в существующую связь |
| «Удалить выбранный переход» | Удаляет только стрелку; блоки остаются |

### 11.5. Начало маршрута и координаты

Выберите блок → «Начать маршрут с этого блока». Это меняет основной вход карты. Если конкретная услуга имеет собственный вход, её «Начальный блок» настраивается отдельно.

«Расположение и стабильные параметры» → X/Y позволяет точно задать координаты без перетаскивания. Координаты не влияют на ответы, условия и очередь.

### 11.6. Копирование блока

Выберите блок → «Копировать блок». Появится копия с новыми ключами. Проверьте её вопросы, назначения фактов и стрелки. Копирование не заменяет настройки обработки и не делает новый базовый тип обращения.

### 11.7. Удаление блока

1. Выберите блок → «Удалить блок».
2. В окне посмотрите входящие связи, пункты каталога и зависимости его ответов.
3. В «Что сделать со связями?» выберите «Убрать связи с удаляемым блоком» либо «Перенаправить на другой блок».
4. Если блок является входом услуги, в «Пункты каталога» выберите «Убрать из черновика» либо «Переназначить другому блоку».
5. При перенаправлении выберите «Перенаправить на».
6. Нажмите «Подтвердить удаление блока».
7. Проверьте карту. Если ошиблись, нажмите «Отменить изменение».

«Отмена удаления» закрывает окно. Если ответы блока используются в условиях, сначала исправьте эти зависимости; иначе подтверждение недоступно. Удаление входа из черновика меняет действующую версию только после новой публикации.

## 12. «Вопрос»: все поля и типы ответов

Нажмите «+ Вопрос» или добавьте «Спросить сотрудника» через «+» существующего шага. Выберите блок и откройте вкладку «Настройки» справа.

### 12.1. Основные поля

| Поле | Что вводить и за что отвечает |
| --- | --- |
| «Что спросить?» | Текст, который понимает сотрудник, например «Какой принтер не печатает?» |
| «Тип ответа» | Как сотрудник вводит/выбирает ответ |
| «Обязательный ответ» | Требует заполнения перед продолжением |
| «Разрешить „Не знаю“» | Даёт отдельный неизвестный ответ; это не то же самое, что произвольный текст «не знаю» |
| «Подсказка» | Пояснение, где найти нужную информацию |
| «Пример ответа» | Образец в пустом поле; не является уже введённым ответом |
| «Название шага на карте» → «Название блока» | Внутреннее имя шага; при одном вопросе карточка на карте показывает формулировку вопроса |

### 12.2. Типы ответа

| Тип | Когда использовать |
| --- | --- |
| «Короткий текст» | Название, номер, короткое пояснение |
| «Длинный текст» | Подробное описание проблемы |
| «Список» | Один вариант из раскрываемого списка |
| «Один вариант» | Один вариант, показываемый набором вариантов выбора |
| «Несколько вариантов» | Можно отметить несколько значений |
| «Да / нет» | Булев ответ; для явного «Не знаю» включите отдельную настройку |
| «Число» | Количество, номер в числовом виде, числовые сравнения |
| «Дата» | Календарная дата |
| «Дата и время» | Дата с временем |
| «Телефон» | Контактный телефон |
| «Email» | Адрес электронной почты |
| «Ссылка» | Адрес страницы/ресурса |
| «Пользователь» | Выбор доступной серверу учётной записи |
| «Подразделение» | Выбор доступного подразделения |
| «Расположение» | Выбор местоположения из серверного контекста |
| «Устройство» | Выбор устройства с серверной проверкой доступности/принадлежности |
| «Услуга» | Выбор доступной услуги |
| «Вложение — защищённый backend пока недоступен» | Сейчас выбрать нельзя; загрузка файлов до создания обращения в этом редакторе не реализована |

Доступность выбора сущностей зависит от серверного контекста. Не вводите технические идентификаторы вместо штатного выбора.

### 12.3. Варианты списка

Для «Список», «Один вариант», «Несколько вариантов»:

1. Заполните «Вариант 1», «Вариант 2» понятными подписями.
2. Нажмите «Добавить вариант» для новых значений.
3. «Удалить вариант N» удаляет вариант; один должен остаться.
4. «Расширенные настройки» каждого варианта показывают «Машинное значение».

Машинное значение используется в сохранённых ответах и условиях. Переименование подписи и изменение значения — разные действия. После изменения значения исправьте использующие его условия и проверьте обработку. Если список импортирован из обязательной формы, сохраняйте значения, ожидаемые её политиками.

### 12.4. Несколько вопросов на странице

1. Раскройте «Вопросы на одной странице и порядок».
2. В «Расположение вопросов» выберите «Группа вопросов» или «Разделы».
3. Нажмите «Добавить вопрос».
4. Выберите вопрос в списке «Вопросы страницы».
5. Заполните его редактор.

| Кнопка/режим | Назначение |
| --- | --- |
| «Один вопрос» | Страница ровно с одним вопросом; добавление/копирование вопросов недоступно |
| «Группа вопросов» | Несколько вопросов одной группой |
| «Разделы» | Несколько вопросов с именованными разделами |
| «Добавить вопрос» | Добавляет вопрос после выбранного |
| «Копировать вопрос» | Создаёт копию с новым ключом |
| «Вопрос вверх», «Вопрос вниз» | Меняют порядок на этой странице |
| «Удалить вопрос» | Удаляет выбранный вопрос, если он не последний и не используется в зависимостях |

В режиме «Разделы» выберите вопрос → «Раздел вопроса». В «Раздел» выберите существующий или «Общие вопросы». Для нового введите «Новый раздел» → «Создать раздел для вопроса». «Название раздела» переименовывает раздел у всех вопросов этой группы.

### 12.5. Расширенные настройки вопроса

| Настройка | Назначение |
| --- | --- |
| «Когда показывать вопрос» | Показывает вопрос только при выполнении условия |
| «Когда ответ обязателен» | Условная обязательность |
| «Минимум символов», «Максимум символов» | Ограничения длины поддерживаемого ответа |
| «Минимальное число», «Максимальное число» | Диапазон числового ответа |
| «Назначения ответа» | Объясняют, для каких целей передавать ответ в обработку |
| «Ключ факта» | Техническое имя для сопоставления с обработкой; без отдельного значения используется ключ поля |
| «Прежние ключи (через запятую)» | Технические альтернативные ключи совместимости; до восьми |
| «Стабильный ключ» | Идентификатор вопроса, созданный редактором |
| «Используется в условиях» | Список зависимостей; помогает понять, что исправлять перед удалением |

Сначала создайте и соедините предыдущий вопрос, затем задавайте условия на его ответ. Недостижимые предыдущие вопросы не становятся доступными только потому, что стоят выше в списке.

### 12.6. «Назначения ответа»

| Назначение | Для чего используется |
| --- | --- |
| «Показать ответ» | Отображение собранной информации |
| «Влияние на приоритет» | Данные о масштабе влияния |
| «Срочность» | Данные о срочности/возможности продолжать работу |
| «Важность» | Дополнительное измерение приоритетной политики |
| «Маршрутизация» | Входное значение для правил маршрута |
| «Вход диагностики» | Назначение данных для диагностической обработки; не включает реальную диагностику |
| «Участник согласования» | Данные для согласования с серверной проверкой доверенного источника |
| «Подтверждение закрытия» | Информация, относящаяся к закрытию |
| «Отчётность» | Измерение для отчётов |
| «Факт паспорта» | Сопоставление с контекстом/паспортом |
| «Публичный ответ» | Назначение данных как публичного ответа; итоговая видимость всё равно проверяется сервером |

Один вопрос может иметь несколько совместимых назначений. Приоритетные назначения доступны для списка, одного варианта, числа и «Да / нет»; участник согласования — для выбора пользователя или подразделения. При смене типа несовместимые назначения снимаются.

Галочка назначения **не задаёт** конкретный приоритет или очередь сама по себе. Политика должна понимать ключ факта и значения. Для обязательных данных существующего типа используйте «Добавить обязательные вопросы типа обращения», чтобы получить канонические ключи и назначения, а не придумывать их заново.

## 13. «Инструкция»

1. Добавьте «+ Инструкция» или «Показать инструкцию» через меню следующего шага.
2. Заполните «Название блока», например «Проверьте питание принтера».
3. В «Текст инструкции» напишите короткие конкретные действия сотрудника.
4. Если нужно подтверждение, включите «Требовать подтверждение прочтения».
5. При необходимости в «Расширенные настройки» выберите «Формат текста»: «Обычный текст» или «Markdown».
6. В «Соединить с блоком» выберите дальнейший шаг, обычно «Проверка результата».

Сотрудник увидит текст и подтверждение «Инструкция выполнена». При требуемом подтверждении обычное продолжение недоступно до отметки. Настройка формата не разрешает исполняемый HTML.

### Кнопка «Нужна помощь поддержки» без выполнения инструкции

1. Создайте блок «Сводка» для передачи в поддержку.
2. Соедините инструкцию с этой сводкой.
3. Нажмите соответствующую стрелку.
4. В «Условие перехода» нажмите «Добавить условие».
5. В «Источник» выберите «Результат текущего блока».
6. После выбора источника задайте «Правило» → «Равно».
7. В «Значение условия» выберите «Нужна помощь поддержки».
8. Сохраните и проверьте через «Тестировать».

Такой явный переход на сводку разрешает отдельную кнопку поддержки. Он не должен перекрываться более ранней совпадающей ветвью. Обычный переход после прочтения и кнопка поддержки — разные исходы инструкции.

## 14. «Условие»: ветви и редактор правил

«Условие» не задаёт нового вопроса. Оно автоматически выбирает маршрут по уже полученным ответам. Отдельная страница сотруднику не показывается.

### 14.1. Настройка развилки по кликам

Пример: ответ «Тип устройства» определяет, показать инструкцию принтера или передать в поддержку.

1. Создайте предыдущий вопрос «Какое устройство не работает?».
2. Выберите тип «Один вариант» и варианты «Принтер», «Ноутбук».
3. Добавьте блок «Условие».
4. Соедините вопрос с условием.
5. Создайте целевые блоки инструкции и сводки поддержки.
6. Выберите условие на карте.
7. В «Добавить условную ветвь» выберите инструкцию принтера.
8. В появившейся «Ветвь N» проверьте «Следующий блок».
9. В редакторе «Если» выберите «Источник» → «Какое устройство не работает?».
10. Выберите «Правило» → «Равно».
11. Выберите «Значение условия» → «Принтер».
12. В «Если ни одно условие не выполнено» выберите сводку поддержки.
13. Настройте продолжение инструкции и сводки.
14. Сохраните карту и протестируйте оба ответа.

Если «Добавить условную ветвь» недоступно и показано «Сначала соедините предыдущий вопрос …», ответ ещё не доступен этому блоку по графу. Добавьте входящую связь от вопроса.

### 14.2. Поля и действия ветви

| Элемент | Назначение |
| --- | --- |
| «Добавить условную ветвь» | Выбор цели создаёт новую ветвь с условием |
| «Следующий блок» | Куда идти при совпадении |
| «Если» | Редактор правила совпадения |
| «Удалить ветвь N» | Удаляет выбранную ветвь |
| «Если ни одно условие не выполнено» | Один явный запасной маршрут |

Не оставляйте незаданный запасной маршрут, если для возможного ответа не гарантирована подходящая ветвь.

### 14.3. Общий редактор условий

Он используется для стрелок, ветвей, видимости и обязательности вопросов.

| Кнопка/поле | Назначение |
| --- | --- |
| «Добавить условие» | Включает условие для выбранного объекта |
| «Убрать условие» | Удаляет проверку. Для стрелки это превращает её в безусловный запасной переход |
| «Источник» | Ответ текущего/предыдущего доступного вопроса или результат текущего блока |
| «Правило» | Оператор сравнения/сочетания |
| «Значение условия» | Значение, с которым сравнивать; варианты выбираются по подписям |
| «Допустимые значения» | Набор значений для «Один из» |
| «Список значений» | При свободном вводе — каждое значение на новой строке |
| «Ещё условие» | Добавляет часть составного условия |
| «Удалить недопустимое значение» | Убирает старое значение, которого больше нет среди вариантов |

При смене «Источник» редактор сбрасывает правило на «Ответ задан», чтобы не сохранить несовместимое сравнение. Поэтому выбирайте **источник → правило → значение** в таком порядке.

| Правило | Значение |
| --- | --- |
| «Равно» | Ответ точно равен значению с учётом типа |
| «Не равно» | Полученный ответ отличается от значения; отсутствующий ответ не считается автоматически таким совпадением |
| «Больше», «Не меньше», «Меньше», «Не больше» | Числовое сравнение; доступно для числового вопроса |
| «Один из» | Ответ совпадает хотя бы с одним допустимым значением; у нескольких выбранных вариантов достаточно одного пересечения |
| «Ответ задан» | Есть непустой ответ. «Нет» в поле «Да / нет» — заданный ответ; неизвестное `null` — нет |
| «Все условия» | Должны выполниться все вложенные условия |
| «Любое условие» | Достаточно одного вложенного условия |
| «Не выполняется» | Инвертирует вложенное условие |

Проверка «Ответ задан» не означает «ответил Да». Для булевого «Да» используйте «Равно» → «Да».

### 14.4. Если подходит несколько ветвей

Откройте нужную стрелку → «Расширенные условия» → «Приоритет сопоставления». Меньшее число проверяется раньше. При равном/неуказанном приоритете имеет значение порядок ветвей. Лучше делать условия взаимоисключающими. Безусловный запасной путь применяется после условных.

Это порядок **выбора ветви**, а не приоритет создаваемого обращения.

## 15. «Проверка результата»

Этот блок задаёт сотруднику проверку решения: «Да», «Нет» или «Не знаю».

1. Добавьте «+ Проверка результата» после инструкции.
2. Назовите блок, например «Печать восстановлена?».
3. Создайте результат «Завершить без обращения» и сводку для поддержки.
4. В «Добавить условную ветвь» выберите завершение без обращения.
5. В этой ветви выберите «Источник» → «Результат текущего блока», «Правило» → «Равно», значение → «Да».
6. Добавьте ветвь на поддержку со значением «Нет».
7. В «Если ни одно условие не выполнено» выберите поддержку для «Не знаю».
8. Протестируйте все три ответа.

В тестировании кнопки называются «Да, решено», «Нет, нужна помощь», «Не знаю».

«Завершить без обращения» должно быть достижимо по подтверждённому положительному результату. Не направляйте туда «Не знаю» или обычный безусловный переход без проверки решения.

## 16. «Диагностика»

В текущей версии диагностика до создания обращения **недоступна для реального запуска**. Блок позволяет настроить безопасный запасной маршрут и проверить неуспешные исходы в симуляции.

1. Добавьте «+ Диагностика».
2. Назовите проверку понятным именем.
3. Проверьте «Запрашивать согласие».
4. В «Соединить с блоком» задайте запасной шаг, например инструкцию или сводку поддержки.
5. В «Расширенные настройки» при необходимости измените «Ожидание, секунд» в пределах 1–120.
6. Убедитесь, что указан «Запасной шаг».
7. В «Тестировать» проверьте исходы диагностики.

| Поле | Назначение |
| --- | --- |
| «Запрашивать согласие» | Настройка необходимости согласия; не является реальным разрешением на операцию |
| «Возможность диагностики» | Сейчас фиксированный вариант «Контекст устройства (пока недоступно)» |
| «Ожидание, секунд» | Настройка тайм-аута; она не делает недоступную операцию доступной |
| Запасной переход без условия | Куда идти, если проверка не выполнена |

В симуляции доступны «Недоступно», «Согласие не получено», «Истёк срок ожидания», «Возможность проверки отсутствует». Реальная операция и проверенные диагностические факты при этом не создаются.

## 17. «Сводка»

1. Добавьте «+ Сводка» перед созданием обращения.
2. Задайте «Название блока», например «Проверьте ответы».
3. Соедините предыдущие вопросы/неуспешные ветви со сводкой.
4. В «Соединить с блоком» выберите результат создания обращения.

Сводка автоматически показывает собранные ответы; вручную писать шаблон списка ответов не нужно. Она даёт сотруднику возможность проверить данные перед продолжением. В предпросмотре используются демонстрационные ответы, в тестировании — реально введённые тестовые значения.

## 18. «Результат»: обращение или завершение без обращения

Добавьте «+ Результат», затем выберите «Действие по завершении».

### 18.1. «Создать обращение»

1. Выберите результат на карте.
2. В «Действие по завершении» выберите «Создать обращение».
3. В «Тип создаваемого обращения» выберите базовый тип, если карта ещё новая и не привязана.
4. Проверьте показанный «Шаблон заявки».
5. Нажмите «Добавить обязательные вопросы типа обращения».
6. Редактор вставит страницу необходимых вопросов перед этим результатом и выберет её.
7. Проверьте формулировки и варианты. Сохраняйте канонические ключи/значения, требуемые обработкой.
8. Сохраните карту.
9. Вернитесь к результату → «Проверить пример обработки».
10. Пройдите маршрут и проверьте очередь, приоритет, сроки и согласование.
11. Нажмите «Проверить готовность» перед публикацией.

| Поле/кнопка | Назначение |
| --- | --- |
| «Тип создаваемого обращения» | Общая привязка всех результатов карты; после сохранения карты обычно зафиксирована |
| «Шаблон заявки» | Показывает связанную форму/обработку |
| «Повторить загрузку шаблона» | Повторяет загрузку названия/состояния шаблона при ошибке |
| «Добавить обязательные вопросы типа обращения» | Импортирует необходимые вопросы в карту перед этим результатом; действие можно отменить через историю |
| «Проверить пример обработки» | Открывает серверную симуляцию |
| «Проверить готовность» | Открывает подготовку публикации |
| «Создать новый тип обращения» | Для новой непривязанной карты создаёт услугу-черновик с шаблоном |
| «Техническая привязка» | Показывает технические идентификаторы типа и шаблона |
| «Политики обработки и согласование» | Выбор правил для всей карты |

Важные условия:

- Привязка общая для всей карты, а не индивидуальная для каждой конечной ветви.
- Вопросы не становятся пригодными для обработки только потому, что похожи по тексту на поля шаблона.
- Если шаблон содержит неподдерживаемые специальные или сложные условные поля, автоматический импорт может попросить настройку через редактор формы.
- В симуляции результат только рассчитывает обработку. Реальное обращение создаёт сотрудник в настоящем кабинете.

### 18.2. «Завершить без обращения»

1. Выберите результат → «Действие по завершении» → «Завершить без обращения».
2. Заполните «Сообщение о решении», например «Печать восстановлена. Обращение не требуется».
3. Подведите к нему положительную ветвь «Да» из «Проверка результата».
4. Проверьте маршрут через симуляцию и готовность публикации.

Это конечный блок без исходящих переходов. Он должен означать подтверждённое решение, а не отсутствие данных или невозможность диагностики.

## 19. Обработка обращения: политики

Открыть можно двумя путями:

1. «Настройки карты» → «Политики и наследование».
2. Результат «Создать обращение» → «Политики обработки и согласование».

Это настройки **одной общей обработки карты**. Изменение здесь не перепубликовывает политики и не меняет их содержимое.

| Поле | За что отвечает |
| --- | --- |
| «Приоритет по ответам» | Выбор приоритета по проверенным данным и действующим правилам |
| «Маршрут и очередь» | Выбор очереди/маршрута поддержки |
| «Сроки обслуживания» | SLA: сроки первого ответа и выполнения |
| «Внутренние сроки поддержки» | OLA: внутренние сроки подтверждения/обработки |
| «Согласование» | Требование и схема согласования |
| «Уведомления» | Правила уведомлений и групп получателей |
| «Закрытие обращения» | Требования к итогу, коду решения и закрытию |
| «Видимость обращения» | Правила доступа к обращению |

Для каждого поля:

1. Оставьте «Наследовать настройки услуги и шаблона», если базовые правила подходят.
2. Либо выберите подходящую опубликованную действующую политику.
3. Сохраните карту.
4. Пройдите «Тестировать» с разными ответами.
5. Проверьте «Подготовить публикацию».

Если написано «Выбранная политика недоступна», замените ссылку до публикации. «Повторить загрузку политик» перечитывает список после ошибки. Локальные «Расширенные настройки» показывают ссылку политики и шаблон.

«Ответы для обработки» показывает вопросы с назначениями для правил. Это обзор, а не отдельный редактор вопроса. Вернитесь к соответствующему блоку, чтобы изменить роль или ключ факта.

Нельзя задать SLA числом на стрелке или получить нужный приоритет только перестановкой блоков. Итог рассчитывает сервер; проверьте его в симуляции.

## 20. Согласования

### 20.1. Использовать действующую схему

1. На карте нажмите верхнюю кнопку «Согласования».
2. В «Схема для карты» выберите существующую опубликованную схему либо «Наследовать из услуги и шаблона».
3. Вернитесь в «Карта сценария».
4. Сохраните карту и проверьте обработку через «Тестировать».

Выбор меняет ссылку карты на схему. Реальное согласование возникает в жизненном цикле настоящего обращения, не во время настройки или симуляции.

### 20.2. Создать новую схему

1. Нажмите «Создать схему согласования».
2. Заполните «Название».
3. В «Источник согласующего» выберите подходящий доверенный источник.
4. Если выбраны «Выбранные согласующие», отметьте доступные активные учётные записи поддержки/администраторов.
5. Выберите «Режим согласования».
6. Нажмите «Опубликовать схему».
7. Прочитайте предупреждение и нажмите «Подтвердить публикацию схемы».
8. После успеха схема выбирается для текущей карты.
9. Сохраните карту, протестируйте и отдельно опубликуйте её.

| Поле/кнопка | Назначение |
| --- | --- |
| «Руководитель заявителя» | Источник руководителя из доверенных серверных данных |
| «Владелец сервиса» | Ответственный владелец сервиса из действующей настройки |
| «Руководитель очереди» | Руководитель выбранной очереди |
| «Выбранные согласующие» | Явный выбор действующих учётных записей по именам |
| «Достаточно одного» | Достаточно решения одного согласующего |
| «Все согласующие» | Требуется согласование всех |
| «Последовательно» | Решения проходят по очереди |
| «Новая версия схемы» | Открывает редактор на базе выбранной схемы с сохранением её дополнительных параметров |
| «Расширенные настройки» | Показывает ключ схемы |
| «Опубликовать схему» | Открывает подтверждение публикации политики |
| «Подтвердить публикацию схемы» | Публикует политику согласования в реестре |
| «Отмена» в подтверждении | Возвращает к редактированию схемы |
| «Закрыть редактор схемы» | Закрывает редактор без публикации |
| «Повторить», «Повторить загрузку согласующих» | Повторяют соответствующую загрузку |

Публикация новой версии общей схемы — отдельное изменение политики Helpdesk. Проверьте, какие другие услуги её используют, прежде чем подтверждать.

Недоступного старого согласующего нужно явно снять; затем выбрать доступного. Для явного источника нужен хотя бы один доступный согласующий. Выбор произвольного пользователя в вопросе не выдаёт ему автоматически полномочия согласования.

Динамическое раскрытие групп согласующих в текущем сервере не поддержано. Существующую групповую конфигурацию нельзя считать проверенной только потому, что она отображается. Используйте поддерживаемый источник и проверяйте наличие доверенных данных.

## 21. Предпросмотр страницы сотрудника

### Быстрый просмотр выбранного блока

1. Выберите блок на карте.
2. Справа нажмите «Как у сотрудника».
3. Проверьте текст, типы контролов, подсказки и компоновку.
4. «Настройки» возвращает редактор.

### Полная страница

1. Нажмите «Предпросмотр страницы» в панели карты либо «Открыть полную страницу» справа.
2. В «Страница для предпросмотра» выберите шаг.
3. Проверьте оформление и длину текстов.
4. Для проверки логики нажмите «Пройти маршрут с начала»: откроется серверное «Тестировать».
5. «Вернуться к карте» или Escape закрывают просмотр.

| Особенность | Как понимать |
| --- | --- |
| Вводимые ответы | Локальные демонстрационные значения; в заявку не сохраняются |
| «Продолжить», «Завершить», «Проверить обработку», ответы проверки результата | В визуальном предпросмотре заблокированы специально; это не проход маршрута |
| Условные вопросы | Для осмотра оформления могут показываться все; реальную видимость проверяйте в тестировании |
| «Условие» | Отдельной страницы сотруднику не имеет |
| «Диагностика» | Не запускается |
| «Сводка» | Показывает примеры ответов |

Не используйте внешний вид предпросмотра как доказательство готовности публикации.

## 22. Серверное тестирование маршрута

1. Сначала сохраните черновик.
2. Нажмите «Тестировать».
3. В «Точка входа для проверки» выберите конкретную услугу/вход либо «Совместимый вход карты».
4. Если есть диагностика, выберите её тестовый исход в «Исходы диагностики только для симуляции».
5. Нажмите «Начать проверку».
6. Отвечайте на вопросы и нажимайте «Продолжить проверку».
7. На инструкции отметьте «Инструкция выполнена», если требуется, либо используйте настроенную «Нужна помощь поддержки».
8. На проверке результата нажмите «Да, решено», «Нет, нужна помощь» или «Не знаю».
9. Дойдите до результата и изучите расчёт обработки.
10. «Назад в проверке» возвращает на предыдущий пройденный шаг.
11. «Начать проверку» начинает новый прогон с начала.
12. Повторите для остальных вариантов и каждого входа.

### Поля и кнопки тестирования

| Элемент | Назначение |
| --- | --- |
| «Точка входа для проверки» | Выбирает маршрут конкретного пункта каталога |
| «Сообщённые и проверенные сведения» | Разделяет исходный симптом, введённые ответы и диагностические факты |
| «Исход симуляции: …» | Имитирует неуспешный исход диагностики; смена исхода сбрасывает текущий прогон |
| «Начать проверку» | Запрашивает первый шаг сохранённой версии |
| «Не знаю» у вопроса | Передаёт явное неизвестное значение для разрешённого вопроса |
| «Продолжить проверку» | Передаёт тестовый ответ/результат на сервер |
| «Инструкция выполнена» | Подтверждение инструкции |
| «Нужна помощь поддержки» | Разрешённый специальный переход инструкции на сводку |
| «Да, решено», «Нет, нужна помощь», «Не знаю» | Исход проверки результата |
| «Назад в проверке» | Повторно строит прогон без последнего шага |
| «Исправить шаг» | Открывает блок, в котором найдена проблема |
| «Настроить данные обращения» | Открывает результат, если не хватает данных формы/обработки |
| «Закрыть панель» | Возвращает обычные настройки справа |

### Что читать в результате обработки

- Пройденная последовательность шагов.
- Рассчитанный приоритет и, в раскрытии, основание расчёта.
- Очередь поддержки.
- Срок первого ответа и выполнения.
- Внутренние сроки поддержки, если настроены.
- Требование согласования.
- Требования закрытия.
- Проверенные ответы для обработки.
- Правила уведомления групп: **сообщения не отправлялись**, доставку провайдера симулятор не подтверждает.

Если маршрут дошёл до создания обращения, но показано, что шаблон требует дополнительных данных, это не успешная проверка обработки. Нажмите «Настроить данные обращения», добавьте обязательные вопросы и повторите прогон.

Сообщение «Проверяется только допустимая часть выбранного входа» означает ограниченный прогон. Остальные ошибки карты могут по-прежнему блокировать публикацию.

## 23. Публикация карты

1. Закончите настройку и нажмите «Сохранить черновик».
2. Дождитесь сообщения о сохранённой ревизии.
3. Проверьте все входы и ветви через «Тестировать».
4. Нажмите «Опубликовать».
5. В панели «Готовность к публикации» нажмите «Подготовить публикацию».
6. Дождитесь серверной проверки.
7. Прочитайте состояние готовности, число проверенных исходов и каждую ошибку.
8. При ошибке нажмите «Исправить: …», исправьте настройки, сохраните и подготовьте публикацию заново.
9. Прочитайте «Изменения относительно опубликованной версии».
10. Если готовность подтверждена, отметьте «Изменения проверены, подтверждаю публикацию».
11. Нажмите «Опубликовать сценарий».
12. Дождитесь сообщения «Опубликована версия N».
13. Используйте «Открыть сценарий сотрудника» для проверки опубликованного результата в настоящем кабинете.

| Элемент | Назначение |
| --- | --- |
| «Подготовить публикацию» | Проверяет сохранённую карту и текущую обработку, готовит список изменений |
| «Policy Health» | Состояние политик; само по себе не заменяет готовность маршрута |
| «Готовность: проверена / есть препятствия» | Можно ли переходить к подтверждению |
| «Проверено исходов» | Сколько допустимых вариантов проверил сервер |
| «Исправить: …» | Переводит к соответствующему блоку, связи или политике |
| «Изменения относительно опубликованной версии» | Показывает, что будет изменено |
| Галочка подтверждения | Явное подтверждение проверенных изменений |
| «Опубликовать сценарий» | Создаёт новую опубликованную версию и делает её действующей |
| «Открыть сценарий сотрудника» | Открывает настоящую опубликованную услугу |

После изменения черновика, обработки или истечения подтверждения нужно подготовить публикацию заново. Публикация связывается с проверенной сохранённой версией; старое подтверждение не применяется к новым правкам.

У новой услуги, созданной внутри карты, может быть включено совместное опубликование услуги со сценарием. Проверьте это в списке изменений, особенно строку «Опубликовать новую услугу со сценарием». Услугу с обычной формой можно опубликовать отдельно через «Доступность».

Изменение черновика уже опубликованной карты не меняет действующую версию до новой публикации. Удалённый из черновика вход тоже может оставаться действующим в прежней версии.

## 24. Версии, копия, архив и конфликты сохранения

### 24.1. Вернуть опубликованную версию в черновик

1. Сохраните либо явно отбросьте текущие изменения.
2. Нажмите «Версии».
3. Справа нажмите «История версий».
4. В «Версия для черновика» выберите нужную опубликованную/ранее опубликованную версию.
5. Нажмите «Вернуть выбранную версию в черновик».
6. Проверьте получившуюся карту.
7. Для применения сотрудникам снова выполните тестирование и публикацию.

Возврат заменяет сохранённый черновик, но сам не переключает действующую публикацию. Если история не загрузилась, повторите «История версий». Если опубликованных версий нет, возвращать нечего.

### 24.2. Создать копию карты

1. Откройте карту.
2. Сохраните изменения, если они есть.
3. Нажмите «Создать копию» под рабочей областью.
4. Проверьте название, входы, вопросы, привязку и политики копии.
5. Сохраните копию отдельно и публикуйте только после проверки.

Копия карты — отдельный сценарий; это не способ добавить ещё один вход в ту же карту. Для общей карты используйте раздел 9.

### 24.3. Архивировать сценарий

1. Откройте карту и сохраните её без незавершённых правок.
2. Нажмите «Архивировать сценарий».
3. Прочитайте предупреждение: новые пользовательские сеансы этого сценария будут недоступны.
4. Нажмите «Подтвердить архивирование» либо «Отмена».

Архив — изменение доступности сценария, а не удаление одного блока. Из каталога история остаётся доступной через «Помощь сотруднику» → «Архив карт услуги» → «Открыть архивную карту».

### 24.4. Сохранение и предупреждения

Сохранённые привязанные карты могут автоматически сохранять корректные изменения. Следите за статусом: «Изменения не сохранены», «Сохранение черновика…», «Черновик сохранён. Ревизия N». Для первой сохранённой версии нужна привязка к типу обработки. Автосохранение не означает публикацию.

| Кнопка/сообщение | Как действовать |
| --- | --- |
| «Сохранить черновик» недоступна | Проверьте права, название, тип обработки, отсутствие запроса/конфликта и наличие изменений |
| «Загрузить серверную версию» | Явно заменяет локальные изменения текущей серверной версией; сначала сохраните важные тексты отдельно |
| «Уйти без сохранения» | Подтверждает потерю локальных правок при возврате в каталог |
| «Переключить без сохранения» | Подтверждает отказ от правок при выборе другой карты |
| «Отмена» предупреждения | Остаётесь в текущем редакторе с введёнными изменениями |
| Предупреждение браузера при закрытии | Не закрывайте страницу, если ещё нужны несохранённые правки |

При конфликте ревизий автосохранение останавливается и локальные правки остаются. Не нажимайте многократно сохранение в надежде затереть чужую версию: получите актуальную версию и повторно примените необходимые изменения.

## 25. Готовые сценарии создания по кликам

### A. Обычная форма «Заказать оборудование»

1. «Создать услугу» → «Обычная форма · новый тип обращения».
2. Выберите опубликованный раздел «Рабочее место» или его аналог.
3. Название: «Заказать оборудование».
4. Описание: «Запрос нового оборудования или замены».
5. «Расширенные настройки обращения» → «Класс обращения» → «Запрос услуги».
6. «Шаблон обработки» → подходящий опубликованный шаблон.
7. Если подходящего шаблона нет: «Создать шаблон» → название → вопросы → политики → «Опубликовать шаблон» → «Подтвердить публикацию шаблона».
8. Вернитесь → «Обновить список шаблонов» → выберите шаблон.
9. «Создать черновик услуги».
10. «Основное» → категория и слова «оборудование», «клавиатура» по строкам → «Сохранить».
11. «Доступность» → проверьте видимость → «Опубликовать услугу» → «Подтвердить публикацию услуги».

Проверка: сотруднику открывается обычная форма, карта не требуется.

### B. Пошаговый запрос «Нужен доступ к папке»

1. «Создать услугу» → «Новая услуга с пошаговым сценарием» → «Создать карту».
2. Название: «Нужен доступ к папке»; раздел «Доступы» или подходящий аналог.
3. Основа: «Простая заявка».
4. Раскройте «Тип обращения» → выберите действующий тип запроса доступа.
5. «Создать карту →».
6. Первый вопрос → «Что спросить?» → «К какой папке нужен доступ?»; тип «Короткий текст»; обязательный ответ.
7. «Вопросы на одной странице и порядок» → «Группа вопросов» → «Добавить вопрос».
8. Новый вопрос: «Зачем нужен доступ?»; тип «Длинный текст».
9. Результат «Создать обращение» → «Добавить обязательные вопросы типа обращения».
10. Проверьте добавленную страницу и соединения; она должна быть пройдена до результата.
11. «Согласования» → подходящая опубликованная схема либо наследование.
12. «Карта сценария» → «Сохранить черновик».
13. «Тестировать» → выберите вход → «Начать проверку» → заполните данные → проверьте сводку и обработку.
14. «Опубликовать» → «Подготовить публикацию» → устраните ошибки → подтверждение → «Опубликовать сценарий».

Проверка: вопросы, сводка и поддержка; согласование рассчитывается сервером по выбранным правилам.

### C. Самопомощь «Принтер не печатает»

1. Создайте новую карту по основе «Диагностика проблемы» и привяжите действующий тип проблем с принтером.
2. «Первый шаг решения» → название «Проверьте питание и бумагу».
3. «Текст инструкции» → опишите проверку питания, бумаги и сообщения на панели принтера.
4. «Проблема решена?» → название «Принтер печатает?».
5. Проверьте ветвь «Да» → завершение без обращения.
6. Проверьте ветвь «Нет» и запасной путь → «Передать в поддержку».
7. На результате «Создать обращение» добавьте обязательные вопросы типа.
8. При желании настройте специальную кнопку поддержки у инструкции по разделу 13.
9. Сохраните.
10. Пройдите отдельные тесты: «Да», «Нет», «Не знаю», кнопка поддержки.
11. Для ветвей поддержки проверьте очередь, приоритет и сроки.
12. Подготовьте и подтвердите публикацию.

Проверка: только подтверждённое «Да» завершает без обращения; «Нет»/«Не знаю» не оставляют сотрудника без помощи.

### D. Ручная карта с развилкой

1. «Создать услугу» → новая карта → «Пустая карта»; задайте раздел, название и тип обработки.
2. «+ Вопрос»: «Какое устройство не работает?» → «Один вариант» → «Принтер», «Ноутбук».
3. «+ Условие»: «Выбор инструкции».
4. «+ Инструкция»: «Проверка принтера»; заполните текст.
5. Ещё «+ Инструкция»: «Проверка ноутбука»; заполните текст.
6. «+ Проверка результата»: «Помогло?».
7. «+ Сводка»: «Проверьте данные для поддержки».
8. Два «+ Результат»: один «Создать обращение», другой «Завершить без обращения».
9. Выберите вопрос → «Соединить с блоком» → «Выбор инструкции».
10. Выберите условие → ветвь на принтер → источник предыдущего вопроса → «Равно» → «Принтер».
11. Вторая ветвь → инструкция ноутбука → «Равно» → «Ноутбук».
12. Запасной путь → сводка поддержки.
13. Обе инструкции соедините с «Помогло?».
14. У «Помогло?» настройте «Да» → завершение, «Нет» и запасной путь → сводка.
15. Сводку соедините с созданием обращения.
16. На результате добавьте обязательные вопросы типа обращения; проверьте вставленную страницу.
17. «Настройки карты» → «Добавить пункт каталога для блока» → первый вопрос.
18. В пунктах первого вопроса задайте публичное название и доступность входа.
19. Сохраните, проверьте каждый вариант и публикуйте после готовности.

Проверка: блоки расположены свободно, но каждая стрелка задаёт нужный маршрут; ничего не зависит от визуального порядка.

### E. «Не печатает» и «Застряла бумага» используют одну карту

1. Подготовьте общую карту печати с общими проверками, сводкой и результатом обращения.
2. Для входа «Не печатает» выберите начальный вопрос.
3. Для входа «Застряла бумага» выберите инструкцию по замятию, если этот путь не пропускает обязательные данные.
4. В каталоге «Создать услугу» → «Вход в существующий сценарий».
5. Выберите общую карту → название «Застряла бумага» → точка входа инструкции → «Создать черновик пункта».
6. Заполните описание/поисковые фразы и сохраните.
7. «Открыть карту сценария» → убедитесь, что выбран нужный начальный блок.
8. «Тестировать» → отдельно выберите каждый вход и пройдите его до результата.
9. Опубликуйте общую карту.

Проверка: в каталоге два названия, общая схема не дублируется. Общие вопросы и обработка сохраняются для обоих входов.

### F. Маршрут с недоступной диагностикой

1. Добавьте вопрос/инструкцию, затем «+ Диагностика».
2. Задайте согласие и тайм-аут.
3. Безусловно соедините диагностику с ручной инструкцией или сводкой поддержки.
4. Не стройте завершение «решено» на предположении, что диагностика сработала.
5. Сохраните → «Тестировать».
6. Отдельно проверьте каждый доступный исход диагностики.
7. Убедитесь, что все неуспешные исходы имеют дальнейший путь.
8. Подготовьте публикацию.

Проверка: сотрудник получает безопасное продолжение; интерфейс не обещает несуществующую автоматическую проверку устройства.

## 26. Частые проблемы

| Проблема | Проверка и действие |
| --- | --- |
| Нет вкладки карт | Это ожидаемо. Выберите услугу → «Открыть карту сценария» |
| Нет кнопки открытия карты | У услуги нет текущей связанной карты. Смотрите «Помощь сотруднику» → «Создать карту»; старые карты — в архиве |
| Не понимаю, где обычная форма | «Создать услугу» → «Обычная форма · новый тип обращения» |
| Не виден нужный шаблон | Он должен быть действующим и опубликованным. После создания нажмите «Обновить список шаблонов» |
| Новый раздел не предлагается при создании формы | Опубликуйте публичный раздел; черновик не подходит для обычной услуги |
| Сотрудник не видит услугу | Проверьте публикацию раздела/типа/карты, форму, видимость входа и категории с её предками |
| Изменил название входа, сотрудник видит старое | Изменён черновик. Опубликуйте новую версию общей карты |
| Нет начального блока | «Настройки карты» → «Основной вход карты»; затем настройте отдельные входы через «Пункты каталога» |
| Блоки есть, но сотрудник до них не доходит | Проверьте входящие/исходящие стрелки; координаты маршрут не задают |
| «Условие» не работает | Сначала соедините предыдущий вопрос; затем источник → правило → значение и запасной путь |
| Изменил источник, исчезло сравнение | Источник сбрасывает правило на «Ответ задан». Повторно выберите нужное правило и значение |
| Ветви перекрывают друг друга | Проверьте взаимоисключение условий и приоритет сопоставления стрелок |
| «Не знаю» ведёт не туда | Настройте отдельную ветвь или безопасный запасной маршрут |
| Не могу удалить блок/вопрос | Исправьте зависимости ответов в условиях; для блока выберите действия со связями и входами в окне удаления |
| После удаления маршрут оборвался | Перенаправьте связи либо отмените удаление и повторите с правильной заменой |
| Не работает «Продолжить» в предпросмотре | Оно специально заблокировано. Для переходов используйте «Тестировать» |
| Тестирование просит сохранить | Сохраните черновик и дождитесь ревизии |
| Маршрут дошёл до результата, но обработка не рассчитана | «Настроить данные обращения» → импорт обязательных вопросов → проверка ролей/ключей/политик |
| Нет очереди/сроков | Проверьте действующие опубликованные политики и существование активной очереди; наследование не гарантирует корректность само по себе |
| Нельзя закончить без обращения | Подведите подтверждённый положительный исход проверки результата |
| Диагностика всегда недоступна | Это текущая граница реализации; нужен запасной путь |
| Не могу добавить вложение | Тип недоступен до реализации защищённого хранения; используйте поддерживаемые вопросы |
| «Опубликовать сценарий» отсутствует | Подготовьте публикацию, исправьте препятствия и дождитесь подтверждённой готовности |
| Подтверждение публикации устарело | Сохраните актуальные изменения и нажмите «Подготовить публикацию» заново |
| Конфликт ревизий | Сохраните важные локальные тексты отдельно, загрузите серверную версию, повторно примените нужные правки |
| После поиска услуги пропали из центра | Сбросьте поиск/статус, нажмите «Все услуги» либо выберите нужный лист дерева |
| Кнопки редактирования серые | Проверьте роль администратора, загрузку/сохранение, открытое подтверждение и незавершённую форму категории |
| У новой категории всё скрыто | По умолчанию категория внутренняя/черновая; проверьте её состояние и видимость родителей |
| Хочу разную обработку в двух входах | Входы одной карты делят общую привязку. Используйте правила, учитывающие собранные данные, либо отдельную карту/тип, если требуется независимая обработка |

## 27. Ограничения и контрольный список

### Текущие ограничения редактора

| Ограничение | Значение/смысл |
| --- | --- |
| Блоки карты | До 256 |
| Вопросы одной страницы | До 100 |
| Варианты одного вопроса | До 100 |
| Переходы одного блока | До 30 |
| Точки входа карты | До 64 |
| Поисковые фразы | До 20, каждая до 100 символов |
| Локальная история изменений карты | До 100 снимков; после перезагрузки используйте сохранённый черновик/версии |
| Названия карты/блока/вопроса/услуги | Обычно до 300 символов в соответствующих полях |
| Текст инструкции | До 10 000 символов |
| Сообщение о решении | До 2 000 символов |
| Тайм-аут диагностики | 1–120 секунд; реальная диагностика до заявки сейчас недоступна |
| Проверка вариантов публикации | Сервер блокирует слишком большой перебор, в том числе более 512 вариантов, либо непрогнозируемые условия обработки |

Если упёрлись в ограничение вариантов публикации, упростите развилки и комбинации влияющих ответов. Не пытайтесь обходить готовность кнопкой сохранения: это другое действие.

### Перед публикацией обычной формы

- Выбран опубликованный публичный раздел.
- Название и описание понятны сотруднику.
- Выбран опубликованный шаблон с нужными полями.
- Проверены очередь, сроки и другие правила обработки.
- Выбраны категория и подходящая видимость.
- Сначала сохранён черновик, затем подтверждена публикация услуги.

### Перед публикацией карты

- У каждого пункта каталога есть существующий первый шаг.
- Все нужные блоки достижимы по стрелкам.
- У каждой развилки есть корректные ветви и безопасный путь «иначе».
- «Нет» и «Не знаю» не завершают проблему как решённую без подтверждения.
- Перед обращением собираются все обязательные данные шаблона.
- Назначения ответов и ключи фактов соответствуют действующим политикам.
- Очередь существует и активна; сроки и согласование проверены сервером.
- Диагностика имеет запасной путь; от неё не ожидают реальной операции.
- Проверены тексты/компоновка через предпросмотр.
- Пройдены серверные тесты каждого входа и основных ответов.
- Сохранена текущая ревизия.
- Подготовлена публикация, прочитан список изменений, устранены препятствия.
- Только после этого нажато явное подтверждение публикации.

## 28. Краткий указатель кнопок и доступности

Основные поля подробно разобраны выше. Здесь собраны действия, которые часто ищут отдельно.

| Ищу действие | Где находится | Почему может отсутствовать/не работать |
| --- | --- | --- |
| Создать обычную форму | Каталог → «Создать услугу» → способ «Обычная форма» | Нет прав администратора, раздела или шаблона |
| Создать новую карту | «Создать услугу» → новая услуга с картой → «Создать карту»; «Новая карта» внутри редактора | Требуются название и раздел в мастере |
| Создать карту для имеющейся услуги | Карточка → «Помощь сотруднику» → «Создать карту» | Карта уже есть или нет шаблона |
| Открыть карту | Кнопка под названием услуги | Нет связанной текущей карты |
| Добавить общий вход | Создание услуги → вход в существующий сценарий | Не выбраны карта, название или первый шаг |
| Добавить вход на карте | Настройки блока → «Пункты каталога для этого шага» | Достигнут лимит входов или нет права редактировать |
| Сохранить услугу | Внизу инспектора услуги | Нет изменений, не заполнено имя, вход ещё загружается или идёт запрос |
| Сохранить карту | Верхняя часть страницы | Нет привязки/названия/прав либо есть конфликт/запрос |
| Проверить внешний вид | «Как у сотрудника», «Предпросмотр страницы» | Для условия нет самостоятельного экрана |
| Пройти ветку | «Тестировать» → вход → «Начать проверку» | Нужен сохранённый сценарий без несохранённых правок |
| Проверить публикацию | «Опубликовать» → «Подготовить публикацию» | Сначала сохраните изменения |
| Применить карту сотрудникам | Галочка подтверждения → «Опубликовать сценарий» | Готовность не подтверждена или подтверждение устарело |
| Добавить обязательные данные | Результат обращения → «Добавить обязательные вопросы типа обращения» | Нет шаблона, запрос идёт или форма содержит неподдерживаемые поля |
| Найти первый шаг | «Начало маршрута» | Основной вход не задан — выберите его в настройках |
| Добавить/удалить стрелку | «Соединить с блоком» / инспектор стрелки | Конечный блок не имеет выходов, цикл запрещён |
| Отменить правку | «Отменить изменение» или Ctrl+Z вне поля ввода | Нет локальной истории; в поле Ctrl+Z отменяет ввод текста |
| Повторить правку | «Повторить изменение», Ctrl+Shift+Z или Ctrl+Y вне поля | Нет отменённых изменений |
| Удалить блок | Выбрать блок → «Удалить блок» → подтвердить | Есть зависимости или не выбран способ перенаправления |
| Восстановить версию | «Версии» → «История версий» → возврат в черновик | Нет опубликованных версий либо есть несохранённые правки |
| Создать копию карты | Под картой → «Создать копию» | Нужна сохранённая карта без текущих правок |
| Архивировать карту | Под картой → «Архивировать сценарий» | Нужна сохранённая неизменённая карта и права администратора |
| Открыть архив | Карточка → «Помощь сотруднику» → «Архив карт услуги» | У услуги нет архивных карт |
| Свернуть/развернуть панели | Панель инструментов карты | Панель теста/публикации может автоматически открыть инспектор |
| Вернуть стандартные размеры | Библиотека → «Найти шаг · расположение панелей» → «Сбросить размеры панелей» | Сбрасывает размеры рабочего места, не маршруты |
| Отменить опасный переход | «Отмена» в предупреждении | Правки остаются в текущем редакторе |
| Повторить загрузку | Кнопка в соответствующем сообщении ошибки | Возобновляет чтение данных, не означает публикацию |

### Что проверено при составлении

Названия и поведение сопоставлены с исходниками текущей Студии: каталог/четыре вкладки услуги, мастер создания, редакторы всех семи типов блоков, вопросы, условия, связи, входы, обработка, согласования, предпросмотр, симуляция, публикация и история. В отдельной вкладке staging проверены создание обычной формы и окно новой карты, пустая локальная карта, библиотека, вопрос и условие. Для проверки инструкции не публиковались услуги/политики, не сохранялась тестовая карта и не создавались обращения. Публикационные действия описаны по текущему коду и существующим проверенным сценариям интерфейса; каждый запуск на вашем каталоге всё равно требует собственной серверной готовности.
