# Эффективность контекста: меньше токенов, быстрее результат

Рекомендации, как тратить меньше токенов при работе с агентом, и какие инструменты помогают агенту искать код и выполнять проверки с меньшим числом шагов.

---

## 1. Как вы (пользователь) экономите токены

### Формулируйте запросы точечно
- **Лучше:** «В `server/websocket/agent_handler.py` поправь таймаут handshake на 30 сек» — агент сразу откроет файл и внесёт правку.
- **Хуже:** «Поправь таймауты везде» — потребуются поиски по кодовой базе и несколько итераций.

### Указывайте контекст через @
- `@server/docs/CODEMAP.md` — агент начнёт с карты сервера, не с полного поиска.
- `@pc_agent/docs/PROTOCOL_V3.md` — при задачах по протоколу агент сразу в контексте.
- `@AGENTS.md` — напоминание про документацию и инварианты.

### Опирайтесь на AGENTS.md
- В AGENTS.md уже есть блок с проектным контекстом (протокол, auth, outbox, модули, playbook и т.д.). Задачи в духе «добавь X в API модулей» агент быстрее решает, зная, что смотреть в `server/docs/MODULES_API.md`.

### Один запрос вместо цепочки
- Вместо: «Найди, где создаётся run_tool» → «Теперь добавь туда лог» — лучше: «В месте, где создаётся run_tool, добавь лог уровня debug».

### Ограничивайте объём правок
- «Исправь только валидацию в `validator.py`» сужает область и уменьшает чтение лишних файлов.

## 2. Что уже помогает агенту (и вам)

- **CODEMAP (server + pc_agent)** — канон только в `server/docs/CODEMAP.md` и `pc_agent/docs/CODEMAP.md` (отдельного CODEMAP в корневом `docs/` для них нет). Структура: точки входа, структура каталогов (таблицы), раздел «Быстрый поиск» (ключевое слово → файлы). Первый шаг навигации без семантического поиска по всей базе. При изменении структуры/маршрутов/ключевых модулей CODEMAP нужно обновлять по критериям из самих CODEMAP и корневого `AGENTS.md`.
- **`docs/QUICK_LOOKUP.md`** — короткий общий индекс тем: что открыть первым, какие документы связаны, какие команды запускать. Используйте его, когда задача затрагивает и сервер, и агент, или когда формулировка ещё широкая.
- **`scripts/diff_context.py`** — самый дешёвый старт при работе от diff: подсказывает темы, стартовые файлы, документы и проверки.
- **`scripts/docs_drift_check.py`** — защита от устаревшей навигации и забытого обновления docs/CODEMAP.
- **`PLANS.md`** — отдельный long-horizon артефакт для длинных задач; хранит актуальное состояние, а не историю чата.
- **Repo-local `.codex/config.toml`** — место для project defaults (модель, reasoning effort, sandbox), чтобы не тащить это в giant prompt.
- **AGENTS.md + подсказка по контексту** — куда идти по темам (протокол, auth, модули и т.д.).
- **Repo-local playbook-и в `.cursor/rules/`** — короткие роутеры и playbook-и; держите always-on только короткие правила, а длинные режимы работы подключайте по ситуации.
- **Скрипты в `scripts/`** — один вызов вместо серии команд:
  - `run_server.py` / `stop_server.py` / `restart_server.py`
  - `run_agent.py` / `stop_agent.py` / `restart_agent.py`
  - `smoke_test.py`, `admin_run_tool.py`
- **Skills** (например, E2E агент, создание/установка модулей) — дают агенту готовый сценарий и снижают число пробных шагов.

## 3. Инструменты, которые можно добавить для экономии токенов

### 3.1 Быстрый поиск по коду (реализовано: `scripts/agent_find.py`)
- **Цель:** один вызов из терминала вместо нескольких grep/semantic search.
- **Использование:**  
  `python scripts/agent_find.py "run_tool"`  
  `python scripts/agent_find.py "outbox_ack" --dir server`  
  `python scripts/agent_find.py "run_tool" --topics-only`
- Вывод: компактный список `файл:строка: фрагмент строки`. Агент или вы сразу видите, где что встречается, и можете открыть нужный файл по пути.

### 3.2 Контекст по diff (реализовано: `scripts/diff_context.py`)
- Если локальная рабочая копия уже `dirty`, начинайте с:
  `python scripts/diff_context.py`
- Результат: компактный план «что открыть сначала / какие docs проверить / какие проверки запустить».

### 3.3 Индекс «где что искать» (реализовано: `docs/QUICK_LOOKUP.md`)
- Файл в виде таблицы: тема → стартовые файлы → связанные docs → команды.
- Это дешевле полного semantic search и особенно полезно для cross-cutting тем.

### 3.4 Проверка «код ↔ docs» (реализовано: `scripts/docs_drift_check.py`)
- Запуск:
  `python scripts/docs_drift_check.py`
- В обычной работе отдельно запускать не обязательно: он уже встроен в `python scripts/verify_workspace.py`.
- Задача скрипта — поймать ситуацию, когда изменили важные entrypoints/flows, а `CODEMAP` или `QUICK_LOOKUP` не обновили.

### 3.5 Один скрипт «все проверки»
- В `pc_client` этой ролью уже пользуется `python scripts/verify_workspace.py`: UTF-8, `py_compile`, JS syntax-check и теперь docs drift.
- Это снижает количество итераций в чате и помогает стабильнее работать в Codex.

### 3.6 UTF-8 bootstrap для Windows shell
- Перед работой с русским текстом в терминале:
  `.\scripts\bootstrap_shell_utf8.ps1`
- Это выставляет UTF-8 для PowerShell и Python IO, чтобы агент не видел mojibake вместо документации и логов.

## 4. Как агенту искать код эффективнее

- **Если уже есть diff — сначала `scripts/diff_context.py`.**
- **Если задача широкая — сначала `docs/QUICK_LOOKUP.md`.**
- **Сначала CODEMAP** для сервера или агента — затем открывать конкретные файлы из карты.
- **Если задача длинная — сначала `PLANS.md`**, а потом уже правки.
- **Grep по каталогу**, а не по всему репозиторию: например, `server/websocket/` вместо корня.
- **Точные символы в grep**: `run_tool`, `outbox_ack`, `handshake` — быстрее и дешевле, чем длинный семантический запрос.
- **Семантический поиск** — когда нужен смысл («где обрабатывается отмена операции»), и лучше ограничивать директорию: `server/api/`, `pc_agent/core/`.
- **Использовать `scripts/agent_find.py`** для быстрого «где встречается X», а `--topics-only` — когда нужен не grep, а стартовый навигационный хинт.

## 5. Краткий чек-лист для запросов

- [ ] Указана ли тема/файл/модуль явно?
- [ ] Использован ли @ на нужный doc/CODEMAP при сложной задаче?
- [ ] Не дублируется ли в чате то, что уже есть в AGENTS.md или правилах?
- [ ] Один запрос вместо цепочки из нескольких мелких?
- [ ] Для «найти и изменить» — сужена ли область (файл/директория)?

Чем точнее запрос и чем лучше агент опирается на CODEMAP, AGENTS.md и скрипты — тем меньше токенов и быстрее результат.
