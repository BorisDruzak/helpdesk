В проверенном пути произвольной проблемы было **11 управляющих действий до
создания** без учёта набора текста и затем отдельное открытие заявки. Поиск по
каталогу может сократить начальный выбор, но не убирает четыре страницы анкеты.

**Согласования сейчас не являются массовым блокером этих публикаций:** среди
активных approval policies нет записей, у 33 услуг не задан
`approval_policy_code`, в прочитанных назначениях веток нет значения
`approval_required=true`. Живая предварительная проверка T-000065 сообщила
«Согласование не требуется». Поэтому сначала нужно упростить форму и убрать
пустой раздел согласований из основного маршрута. Возможность согласования
можно сохранить для будущих отдельных типов обращений.

У опубликованной closure policy `guided_studio_20261011_closure` обязательны
публичный итог и код решения. В legacy status handler подтверждение сотрудником
по умолчанию включено при отсутствии явной политики `required=false`. Для
первого этапа нужно явно определить простую политику завершения и проверить
её во всех используемых обработчиках. Согласие на отдельные операции Endpoint
не следует смешивать с согласованием самой заявки.

## Предлагаемый сценарий первого этапа

Сотрудник: **войти → описать проблему → отправить → общаться в одной карточке**.
Основной экран сразу показывает описание и необязательные вложения. Учётная
запись и контакты подставляются, наличие агента не требуется. Категория помогает
маршрутизации, но незнание категории не препятствует обращению.

Поддержка: **увидеть новую → взять в работу → ответить → указать результат и
закрыть**. Для обычного обращения не нужны отдельное согласование, ручной код,
обязательная оценка и повторное подтверждение сотрудником. Сведения об устройстве,
SLA, диагностика и сложные процессы доступны по необходимости.

Существующая компактная карточка и единая очередь уже дают основу для этого
пути. Полная переработка интерфейса не требуется. Следующий пакет изменений
стоит ограничить входом/подключением сотрудника, короткой формой Студии,
видимым описанием и результатом, простой политикой закрытия.

Дизайн и поведение заявок в этом аудите не менялись. Внедрено только отдельно
запрошенное изменение MFA. Изменения первого этапа выше являются предложением.
