# Единый каталог заявителя

Основной путь: поиск или **Все услуги** → опубликованная услуга → конкретная
проблема → поля/проверки → отправка → чат. Простые формы сохраняют проверку и
отправку на одной странице; сценарии используют серверные шаги и команду `back`.
Проверка профиля, доступность формы, согласия, маршрутизация и создание заявки
остаются в существующих серверных обработчиках.

## Поиск и навигация

- Выдача сгруппирована по опубликованной услуге; видны три проблемы и переход
  **Все проблемы услуги**. По названию услуги без совпавших симптомов доступны
  первые опубликованные проблемы этой услуги. Никакие сценарии не запускаются
  при раскрытии группы.
- Запрос названия услуги, включая исправленную раскладку, поднимает её выше
  частных симптомов. В равной степени совпавших названиях более короткое
  название получает приоритет. Запрос симптома сохраняет прежний порядок точных
  совпадений. ACL-фильтрация и ограничение ответа выполняются до отображения.
- Дублирующие заголовок описания и технические причины совпадений не занимают
  карточку. Исправленная раскладка по-прежнему явно показана.
- Самостоятельные старые формы сохранены со всеми полями в свёрнутом разделе
  **Дополнительные формы**. Их перенос в сценарий допускается только после
  сопоставления всех полей, правил, очередей и SLA; совпадение названий недостаточно.
- Любой новый выбор формы отражается в `offering` или `form`; именованный вход
  сценария использует также `entry`. Назад/Вперёд и обновление восстанавливают
  соответствующий черновик. Повторный выбор текущей формы не теряет ответы старого
  черновика, сохранённого ещё по базовому URL.
- Закрытие каталога кнопкой или Escape сохраняет текущий запрос/форму. Пока каталог
  открыт, форма скрыта без перемонтирования. Смена формы передаёт выбранный компьютер.

## Управление публикацией старых шаблонов

Автоматическое добавление registry-шаблона в публичный pack можно отключить
явным `config.requester_catalog.visible: false`. По умолчанию поведение прежнее.
Этот флаг управляет обнаружением, не заменяет авторизацию или политику создания;
исторические версии/заявки и совместимые обращения по известным шаблонам сохраняются.

`scripts/helpdesk_requester_catalog_cleanup.py` планирует/применяет только
подтверждённый тестовый шаблон `template_1792b61daf914ce5afcd6dd83be9c46f` с точным
названием. Его прежняя услуга уже имеет статус retired. Скрипт запрещает
неадминистративного актёра, другую БД, изменившийся fingerprint и любые
потребляющие услуги, кроме retired. Он публикует новую версию через
`HelpdeskPolicyRepo.publish_request_template`, проверяет неизменность всех полей
обработки до фиксации транзакции и сохраняет штатный аудит. Перед применением
нужны свежая проверенная резервная копия и привязка к точному установленному SHA.
Вернуть обнаружение можно новой штатной публикацией с прежним config; старые
версии не удаляются. Массовая очистка по словам «тест» в названиях не применяется.

## Измерение качества

Сервер пишет строку `[catalog_search]` с числом результатов, услуг, признаком
пустой выдачи и длительностью чтения/поиска в миллисекундах. В этой строке нет
текста запроса, идентификатора сотрудника, содержимого формы или документов.
По ней можно считать долю пустой выдачи и распределение задержек.

Для повторяемого контроля используется фиксированный обезличенный корпус:

```powershell
python scripts/benchmark_requester_catalog.py <public-catalog-snapshot.json>
```

Отчёт содержит первые пять результатов для названий услуг, симптомов, опечаток,
раскладки и неизвестной проблемы. Время этого локального расчёта не включает БД
и сеть. Сквозная аналитика кликов/отказов/времени до отправки пока не имеет
центрального сборщика; не следует выдавать локальные замеры за такую аналитику.

## Проверки

Frontend: `catalog-search.test.tsx`, `catalog-categories.test.tsx`,
`scenario-entrances.test.tsx`, `new-request-page.test.tsx`.
Backend: `test_service_catalog_search.py`, `test_requester_catalog_visibility.py`.
Браузер: `requester-usability.spec.ts` проверяет три ширины, закрытие каталога,
явный выбор входа, историю/обновление и сохранение дополнительных форм.
Релиз собирается отдельно поверх фактического staging SHA; посторонние правки
Studio и более новые изменения стенда не заменяются рабочим деревом целиком.
