# Эффективность Cursor: меньше токенов, быстрее результат

Рекомендации, как тратить меньше токенов при работе с агентом, и какие инструменты помогают агенту искать код и выполнять проверки с меньшим числом шагов.

---

## 1. Как вы (пользователь) экономите токены

### Формулируйте запросы точечно
- **Лучше:** «В `server/websocket/agent_handler.py` поправь таймаут handshake на 30 сек» — агент сразу откроет файл и внесёт правку.
- **Хуже:** «Поправь таймауты везде» — потребуются поиски по кодовой базе и несколько итераций.

### Указывайте контекст через @
- `@server/docs/CODEMAP.md` — агент начнёт с карты сервера, не с полного поиска.
- `@pc_agent/docs/PROTOCOL_V3.md` — при задачах по протоколу агент сразу в контексте.
- `@AGENTS.md` — напоминание про документацию и инварианты.

### Опирайтесь на AGENTS.md
- В AGENTS.md уже есть блок «Подсказка по контексту для Codex» (протокол, auth, outbox, модули, playbook и т.д.). Задачи в духе «добавь X в API модулей» агент быстрее решает, зная, что смотреть в `server/docs/MODULES_API.md`.

### Один запрос вместо цепочки
- Вместо: «Найди, где создаётся run_tool» → «Теперь добавь туда лог» — лучше: «В месте, где создаётся run_tool, добавь лог уровня debug».

### Ограничивайте объём правок
- «Исправь только валидацию в `validator.py`» сужает область и уменьшает чтение лишних файлов.

## 2. Что уже помогает агенту (и вам)

- **CODEMAP (server + pc_agent)** — единая структура в `server/docs/CODEMAP.md` и `pc_agent/docs/CODEMAP.md`: точки входа, структура каталогов (таблицы), раздел «Быстрый поиск» (ключевое слово → файлы). Первый шаг навигации без семантического поиска по всей базе. При изменении структуры/маршрутов/ключевых модулей CODEMAP нужно обновлять (правило `.cursor/rules/codemap.mdc`).
- **AGENTS.md + подсказка по контексту** — куда идти по темам (протокол, auth, модули и т.д.).
- **Правила в `.cursor/rules/`** — проект, автоматизация, сервер, агент, фронт; меньше необходимости каждый раз объяснять контекст.
- **Скрипты в `scripts/`** — один вызов вместо серии команд:
  - `run_server.py` / `stop_server.py` / `restart_server.py`
  - `run_agent.py` / `stop_agent.py` / `restart_agent.py`
  - `smoke_test.py`, `admin_run_tool.py`
- **Skills** (например, E2E агент, создание/установка модулей) — дают агенту готовый сценарий и снижают число пробных шагов.

## 3. Инструменты, которые можно добавить для экономии токенов

### 3.1 Быстрый поиск по коду (реализовано: `scripts/agent_find.py`)
- **Цель:** один вызов из терминала вместо нескольких grep/semantic search.
- **Использование:**  
  `python scripts/agent_find.py "run_tool"`  
  `python scripts/agent_find.py "outbox_ack" --dir server`
- Вывод: компактный список `файл:строка: фрагмент строки`. Агент или вы сразу видите, где что встречается, и можете открыть нужный файл по пути.

### 3.2 Проверка «документация ↔ код»
- Скрипт, который проверяет, что в CODEMAP упомянутые файлы/каталоги существуют, и что ключевые термины из PROTOCOL_V3 встречаются в коде (например, `ws_ticket_v3`, `outbox_ack_v3`).
- Результат: быстрая проверка дрифта без ручного чтения всей документации агентом.

### 3.3 Индекс «где что искать» (расширение AGENTS.md)
- Файл (например, `docs/QUICK_LOOKUP.md`) в виде таблицы: тема → список файлов/доков.  
  Пример: `run_tool` → `server/websocket/ui_handler.py`, `server/app/repos/...`, `server/docs/...`
- Агент по одному чтению файла получает точные пути и меньше семантического поиска.

### 3.4 Один скрипт «все проверки»
- Например, `scripts/check_all.py`: линтер (если есть) + smoke_test + опционально быстрая проверка, что сервер отдаёт health.
- Вы или агент запускаете одну команду после правок вместо перечисления шагов в чате.

### 3.5 Pre-commit / CI
- Линт, тесты, проверка CODEMAP/документации в pre-commit или CI. Агент тогда не тратит токены на «сначала проверь линт, потом тесты» — это уже в пайплайне.

## 4. Как агенту искать код эффективнее

- **Сначала CODEMAP** для сервера или агента — затем открывать конкретные файлы из карты.
- **Grep по каталогу**, а не по всему репозиторию: например, `server/websocket/` вместо корня.
- **Точные символы в grep**: `run_tool`, `outbox_ack`, `handshake` — быстрее и дешевле, чем длинный семантический запрос.
- **Семантический поиск** — когда нужен смысл («где обрабатывается отмена операции»), и лучше ограничивать директорию: `server/api/`, `pc_agent/core/`.
- **Использовать `scripts/agent_find.py`** для быстрого «где встречается X» перед детальным чтением файлов.

## 5. Краткий чек-лист для запросов

- [ ] Указана ли тема/файл/модуль явно?
- [ ] Использован ли @ на нужный doc/CODEMAP при сложной задаче?
- [ ] Не дублируется ли в чате то, что уже есть в AGENTS.md или правилах?
- [ ] Один запрос вместо цепочки из нескольких мелких?
- [ ] Для «найти и изменить» — сужена ли область (файл/директория)?

Чем точнее запрос и чем лучше агент опирается на CODEMAP, AGENTS.md и скрипты — тем меньше токенов и быстрее результат.
