## 2026-04-28 Protocol hardening notes

- `server/websocket/agent_services.py` now marks an `outbox_id` as runtime-deduped only after a terminal non-retryable outcome or ACK. Retryable `outbox_nack` outcomes must remain retryable by the same `outbox_id`.
- `server/websocket/outbox_ingest_components.py` treats missing `trace_id` as an envelope validation error and returns a typed validation NACK with a fallback server trace id instead of silently skipping ACK/NACK.
- `server/websocket/protocol.py` registers sync `send_ws_command(..., wait_for_result=True)` waiters before waking device dispatch, and copies caller params before consuming internal `_operation_id`.
- `server/tools/service.py` also copies caller params before building `run_tool` command params, so retries/logging/audit code can safely reuse the original dict.
- Multi-instance DeviceOutbox dispatch is still blocked. Start with `quality/outbox_multi_instance_prerequisites.json`, `quality/active_risks.json` TD-015, `server/tests/test_outbox_multi_instance_prerequisites.py`, `server/websocket/device_outbox_sender.py`, and `server/app/repos/device_outbox_repo.py`; do not enable more than one dispatching server process until DB coordination, lock ownership, agent connection ownership, lease recovery, and the multi-instance test plan pass.
- `pc_agent/ws_agent.py` handshake diagnostics must log the current `PROTOCOL_VERSION` (`ws_ticket_v3`), not legacy `ws_mcp_v1`.
- `pc_agent/ws_agent.py` classifies only explicit auth handshake rejects (`4003`, invalid-token, token-required) as reprovision triggers; transient WSS/proxy handshakes such as HTTP `502` must stay in reconnect/backoff and must not terminate the agent process.
- Agent device lifecycle events: `pc_agent/ws_agent.py` must pass the canonical `device_id` into `AgentOrchestrator`; `pc_agent/core/orchestrator.py` emits `module_state_changed` and hash-gated `tools_changed`; `pc_agent/core/sender.py` must not serialize the local SQLite compatibility `ticket_id=device_id` as ticket context for Protocol V3 device events.
