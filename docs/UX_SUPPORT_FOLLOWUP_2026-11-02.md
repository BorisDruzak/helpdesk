## Что воспроизведено

- Открытая вкладка пользователя содержала старый bundle `index-BTg9ASH2.js`.
  Проверено отсутствие незаписанного текста; обновление загрузило актуальный
  интерфейс `index-CH9geHHa.js`. Однако оба функциональных дефекта сохранились.
- T-000007 уже имела статус «В работе», но не имела исполнителя. Проверка
  интерфейса учитывала административную роль и предлагала «Решить обращение»;
  проектор взятия отказывал по самому статусу, поэтому назначить себе было неясно.
- В T-000060 тестовый ответ администратора принят сервером с HTTP200 и очищен
  из редактора. Запрос ленты HTTP200 вернул80 старых `sla_reminder_sent`, до
  30 октября включительно. Запрос выбирал первые240 событий по возрастанию,
  затем последние80 из них. Новое сообщение сохранялось за этим окном.

## Поведение после исправления

- Для нового обращения: «Взять в работу»; для уже назначенного себе:
  «Начать работу»; для старого активного обращения без своего назначения:
  «Взять себе». Исполнитель указан рядом со статусом. Дата создания сохранена
  в сведениях, чтобы не уменьшать чат на узком экране.
- Решение через support API требует назначения текущему оператору, в том числе
  администратору. Сам статус «В работе» этого не заменяет. Явное начало работы
  администратором назначает заявку ему в той же транзакции.
- Назначение себе старой активной/ожидающей заявки сохраняет её статус. Команда
  существующего `/assign` получает `claim=true` и `expected_assignee_id`,
  проверяет права, роль, область доступа, статус и исполнителя под блокировкой.
  Конкурирующее назначение получает409. Членство в очереди и лимит нагрузки
  проверяются каноническим сервисом; специфичные причины отказа сохраняются.
- Чат получает последние публичные сообщения отдельно от внутренних заметок.
  Фильтрация выполняется до ограничения SQL-выборки. История сохраняет результаты
  диагностики. Старый метод чтения событий для replay не изменён; сообщения и
  старые события не удалялись и не переписывались.
