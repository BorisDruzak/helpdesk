Пошаговая разработка

На каждом шаге показываем только то, что нужно прямо сейчас, без перегруза полями.
Шаг 1
Если нужен полный контроль над manifest и контрактами, продолжайте в advanced-редакторе. Для обычного сценария достаточно шагов ниже.

Шаг 1. Каркас модуля

Задаём идентичность модуля и минимальные ограничения ещё до инструментов.

Подсказка из guide

  • `module` — это bundle доставки, versioning и ownership, а не один большой скрипт.
  • `platforms` указывайте честно: это влияет и на validate, и на runtime decisions.
  • Reserved namespaces вроде `dns.*` или `network.*` требуют `owner_scope=core|platform|builtin`.
Используйте family-имя пакета доставки: например `network_basic` или `vendor_acme_support`.
Лучше придерживаться semver `x.y.z`, чтобы rollout и diff версий были понятными.
Для reserved namespaces в docs допустимы только `core`, `platform` и `builtin`.
`any` не комбинируется с конкретными платформами.
По одному requirement на строку. Это список пакетов/зависимостей уровня модуля.
Опциональные зависимости, без которых модуль всё ещё может быть опубликован.
`module_api_version` обычно оставляйте `1.0.0`, а `entrypoint` — `module:register`, если не меняете builder/runtime path.

Шаг 2. Инструменты

Собираем модуль из шаблонов и сразу редактируем код и схемы выбранного инструмента.

Правило автора

  • Один tool = одно логическое действие.
  • Canonical tool id должен быть semantic-only: `dns.resolve`, `network.ping`.
  • `params_schema` и `output_schema` обязательны, поэтому ниже есть быстрые doc-примеры.
Формат строки: name:type! | Описание. Типы: string, integer, number, boolean, object, array[string].
Структурируйте output так, чтобы validate и playbook могли на него опираться.

Шаг 3. Политики и исполнение

Собираем runtime-профиль выбранного инструмента без погружения в полный JSON.
Остальные contract-поля, aliases, resources, redaction и dependencies доступны во вкладке «Редактор модулей».

Шаг 4. Проверка и публикация

Сверяем форму локально, прогоняем server-side validate и только потом публикуем модуль в registry.
