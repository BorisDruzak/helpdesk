# Runbook: Инцидент — восстановление БД

## Цель

Действия при потере или порче данных PostgreSQL (отказ диска, случайное удаление, сбой миграции и т.п.).

## Предварительные условия

- Настроены backup и WAL archiving по [RUNBOOK_BACKUP_RESTORE.md](RUNBOOK_BACKUP_RESTORE.md).
- Известна желаемая точка восстановления (PITR) или допустимость восстановления «на последний backup».

## Шаги

### 1. Оценить масштаб

- Определить: полный отказ инстанса или частичное повреждение (таблица, схема).
- Зафиксировать время инцидента и целевую точку восстановления (RPO).

### 2. Остановить приложение

- Остановить сервер приложения (pc_client server), чтобы не писать в повреждённую или восстанавливаемую БД.

### 3. Восстановление из backup

- **Полное восстановление:** по [RUNBOOK_BACKUP_RESTORE.md](RUNBOOK_BACKUP_RESTORE.md) восстановить кластер из последнего base backup.
- **PITR:** задать `recovery_target_time` и при необходимости `restore_command`, запустить инстанс до выхода из recovery.

### 4. Проверка целостности

- Запустить миграции до актуальной ревизии: из каталога `server` выполнить `alembic upgrade head`.
- Проверить ключевые API (health, логин, список тикетов) на восстановленном инстансе.

### 5. Запуск приложения

- Включить сервер приложения, направить трафик на восстановленный инстанс (или переключить конфиг на новый хост БД).

### 6. Пост-инцидент

- Зафиксировать RTO/RPO по факту.
- Обновить runbook при выявлении недостатков процедуры.
